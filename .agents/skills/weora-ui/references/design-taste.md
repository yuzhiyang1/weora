# HeroUI 公开设计原则在 Weora 的落地

来源：[HeroUI Design Taste 公开说明](https://heroui.pro/docs/react/getting-started/design-taste)，核对日期 2026-10-21。公开页介绍十类设计方向，适用于开源 `@heroui/react`。以下是我们据此制定的项目规则，不是官方完整 78 条原则的翻译或复刻；不需要 Pro 组件、模板、个人 Token 或安装器。

## 检查和实现

| 公开方向 | Weora 的具体标准 |
| --- | --- |
| 间距 | 布局使用 Tailwind 的 spacing 标尺（CSS 可用 `calc(var(--spacing) * n)`）；相关内容间隔 2～4 个单位，卡片内边距 4～6 个单位，区块间隔 6～8 个单位。具体数值是项目选择，不声称来自官方完整 Skill。窄屏通过折行、堆叠和局部滚动适配，不缩小文字挤内容。 |
| 字体 | 页面标题 24～28px，区块标题 16px，正文及字段标签 14px，辅助说明 12px。主信息用正常前景色，说明用 muted；不用整页粗体或过小字号制造层级。代码和宽表格可按内容调整。 |
| 颜色 | 使用 HeroUI 的 foreground、muted、surface、accent 及状态令牌。蓝色用于主操作和选中导航，状态色仅表达真实业务状态；加载中或未知状态不显示绿色成功图标或零计数。 |
| 卡片 | 新增及重构卡片优先使用 HeroUI Card 的 Header、Title、Description、Content、Footer 组合；业务 CSS 只布局，不重复设置库已有的背景、圆角、阴影。列表条目不逐个套卡片，同一内容避免重复表面。 |
| 表单 | 同一业务步骤的字段成组，标签始终可见，说明就近。使用现有 secondary 字段变体，错误文字指出如何恢复，失败保留输入。窄屏单列，按钮与相关字段保持邻近。 |
| 按钮 | 一个操作区域突出一个主动作；取消、管理、查看全部降为 secondary、tertiary 或 ghost。使用项目锁定版本支持的官方变体；兼容包装层的 theme/type 映射以实际代码为准，不照抄 Pro API。全局快捷入口不与页面主动作争夺强调色。 |
| 图标 | 常规操作使用 16px、区块使用 20px Lucide 图标，相同上下文保持一致。图标旁已有文字时作为装饰，纯图标按钮有可访问名称。 |
| 导航 | 延续 AppShell 与 HeroUI Tabs。当前位置清楚，菜单与详情切换保留链接、键盘与焦点语义；不因视觉调整另建导航系统。 |
| 可访问性 | 保留 HeroUI 焦点环；业务 Router 链接补充 focus-visible 反馈。支持 Tab、Enter、Escape，关闭弹窗归还焦点。长标题可换行或截断但保留可理解的名称，目标区域有足够点击空间。 |
| 简洁 | 工作页面优先展示任务、资产和下一步操作。移除不帮助决策的宣传大图、装饰性流程和重复入口；确有业务用途的说明、风险提示、统计范围仍保留。 |

## 审查顺序

先在真实页面确定主要任务及最突出操作，再查共享组件与样式。按“信息优先级 → 字体/间距 → 官方组件组合 → 状态/键盘 → 浅深色/窄屏”的顺序修复有证据的问题；不要仅为符合清单重写无关页面。

验收记录写明查看了哪些页面、改了哪些共享规则、哪些业务路径实际操作过。视觉改动优先截图对比；只有新增或改变行为时补充相应测试，不写断言 CSS 数值的镜像测试。
