# Weora 项目知识库设计

以 TeamAI CLI `1104f3058d268e6a00926e1f6d0bd7c724dbe0a6` 的团队上下文为行为基线。对照 [团队上下文](https://github.com/Tencent/teamai-cli/blob/1104f3058d268e6a00926e1f6d0bd7c724dbe0a6/docs/guide/zh-CN/knowledge.md)、`src/contribute.ts`、`src/recall.ts`、`src/maintenance/confidence.ts` 和发布工作流。下表定义目标行为，实际状态见验证记录。

## 用户流程对照

| TeamAI 入口 | Weora 对应行为 |
| --- | --- |
| `contribute --file`、项目或共享 namespace | 工作空间成员贡献 Markdown 经验。指定项目时按现有项目权限校验，未指定时进入共享知识。未指定目录或显式路径时，只有一个生效的经验目录就发布到该目录，否则发布到所选范围的根目录。普通贡献直接发布，版本和审计同事务。离线提交在本机持久排队，作者可在原设备召回、检查相关性及按路径打开，重连按原作用域和原请求键重放。 |
| 会话结束时的摩擦提示和分享流程 | 针对用户纠正、拒绝工具或反复失败的有人值守会话，最多提示一次。用户可审看并确认每条学习内容、作用域、会话共享和评分选项；按 TeamAI 的禁用和退出条件跳过。会话转录和评分使用各自授权与能力。 |
| `session list --finished`、`teamai-finished-sessions` | 交互会话按最后活动时间确认已结束。无人值守启动器在原生进程退出后处理本次任务的根会话，外部运行器可在任务末尾一次处理当前目录记录的会话。两种模式可以询问、自动归档或关闭。归档用脱敏快照，评分用指定的归档版本。 |
| `score --session`、`--team-session`、`--scorer` 与本地标准试跑 | 点名团队评分标准或试跑本地 Markdown 标准，固定本机脱敏证据或团队归档的版本。人工可直接提交标签，模型使用标准和脱敏转录。本机会话只共享标签，按项目和工作空间查找评分结果。 |
| 分享经验时的评分建议 | 询问策略通过经验分享提醒给出预览入口。建议包含采样命中且待评分的标准，成员可改选、确认或跳过。确认才使用预览固定的证据与标准发起评分。 |
| `score --batch` 与团队评分分组 | 一次调用可评估偏好同一客户端和模型的多项会话标准。各项固定标准版本、保留独立标签，后台按调用分组核算日额度并统一结算。 |
| `scorers/<名称>/SCORER.md` 及附件 | 单文件或目录都可发布及试跑。可见文本附件与标准一起固定到版本，点名和后台评分读取对应快照，标签可追溯到目录校验值。 |
| `scorers/<目录>/scoring.yaml` | 管理员按目录保存会话模式、日额度、批处理、自动采纳开关、Skill 路由开关和隔离级别。当前职能与所选项目启用的目录按字段覆盖根设置。多目录同时声明时，会话模式取最严格值，每日额度取最小值，自动采纳和 Skill 路由以停用优先。批处理冲突时暂停该范围的模型评分。 |
| 会话中的 Skill 分发证据 | 原生宿主 Hook 记录会话实际看到的安装代次。归档和本机证据登记按配对设备、项目及安装时段核验，并保存固定的 Skill 摘要和已确认的加载记录。 |
| `import --from-tools`、`--from-iwiki` | 读取调用者授权的来源，分类为 rule、doc、learning，跳过个人内容。人工逐条接受、修改或跳过，显式批量确认，失败可续做。保留同批次和来源定位。 |
| `import --from-mr` | 读取已授权的 PR/MR 元数据、提交、差异和评论，生成一条经验建议并显示重叠项。人工选择接受、改标题或略过；同批按仓库合并更新索引，输出部分失败。 |
| 近期合并提醒 | 会话启动时按当前 checkout 的 GitHub origin 后台查询；下一条可展示的提示词列出待提炼来源。提醒独立于召回与会话经验分享。环境变量、个人覆盖及团队默认值按优先级解析。 |
| `recall`、`recall --check` | 默认检索当前项目及用户有权读取的工作空间共享知识。管理员可以为项目关闭共享继承。输出出处、有限相关关系和代码来源新鲜度。检查模式返回首位相关性、实际得分、阈值、词项覆盖和可见源码出处，无正文、召回记录或来源新鲜度探测。保留用户可见的手工查询。 |
| `recall enable/disable/status` | 自动召回默认关闭。工作空间默认值、成员覆盖与环境变量强制关闭按优先级解析。关闭后撤下自动召回引导，停止自动采纳记录，手工搜索仍可使用。 |
| 代码知识缺口 | 采集时从已提取事实记录外部依赖、未解析导入、接口实现、连接性、错误处理、配置、解析失败和覆盖范围。`recall --check` 可在没有文档命中时返回已登记缺口。已提取的导入位置可按名称、文件或路径查询。平台按项目索引版本读取，离线入口链接当前快照。 |
| 改动入口与候选文件 | 实现和重构使用 lookup。以命中源码或发布事实页的源码锚点选取最多三个入口，展示最多十条正向直接关系和十个候选文件。已有跨仓库关系按同一项目授权及发布状态筛选。需要调用行号时读取对应图谱。 |
| 图谱定向阅读 | 相关性预检通过后，对依赖、调用链、业务场景和多跳关系，按 G1、G2、G5、G6 读取当前项目已发布的图谱文档。单来源可直接打开，多来源按代码索引选择。 |
| `teamai-recall` 角色 | 启用召回且已安装角色时，主会话在需要团队背景的修改、排查和设计前单独委托召回。已有答案、直接可确认的小改动和知识范围外的任务可跳过。角色先执行只读相关性检查。明确只改动单文件或单字段时，可用预检的标题和源码出处直接返回摘要。缺少出处时只召回一条。复杂任务按任务深度继续查询。 |
| `teamai-todowrite-hint` | `TodoWrite` 成功后检查会话召回策略和团队独立开关。每个根会话 24 小时内最多提示一次。工作空间保留内置语言、静态自定义文案及配置审计。 |
| 采纳、手动正负反馈、置信度 | 已召回的知识在同一根会话被打开时计一次采纳，手工反馈也可记录。可选评分器评价未直接打开的命中。按 TeamAI 权重计算活动置信度，保留召回次数、采纳证据及不同计数口径。 |
| `teamai:adoption:<hash>` 生成式问题 | 会话结束后为采集前实际召回、尚未打开或判定的正文生成采纳问题。按版本判断，失败按原证据续做，判定写入已有的采纳账本。 |
| `scorers/teamai-adoption.md` 团队覆盖 | 同名模板可在工作空间或项目发布，项目覆盖优先。标准引用原召回正文的逻辑证据文件。重置当前范围后回退到上级标准或内置标准，已领取的问题沿用展开后的旧版本。 |
| 采纳问题的默认分组 | 同一会话版本里兼容的采纳问题共用一次模型调用。完整的标签集合以同一事务提交，按调用计算额度并保留每条知识的判定。 |
| 普通标准、采纳问题与 Skill 路由的混合分组 | 启用后台合并后，同一会话版本中偏好相同客户端和模型的三类问题可共享调用及一次额度。标签与采纳判定在同一事务结算，失败依原批次续做。 |
| 点名 Skill 路由问题 | 根据会话固定的安装快照，以 `teamai:routing:<skill>` 或 `teamai:routing:<目录>:<skill>` 点名评分。内置标签为 `fit`、`idle`、`extra`、`missed`。支持团队模板、归档及本机会话、人工标签、预览确认和兼容批处理。 |
| Skill 路由自动建议和后台评分 | 开启 `skill_routing` 后，从本人已确认加载情况的会话生成待评分问题。询问模式在评分预览中建议，自动模式按会话成组领取。工作空间按模型调用共用 UTC 日额度，失败续做保留首次领取的证据和模板。 |
| 点名生成式采纳问题 | 从本人会话实际召回过的正文找到 `teamai:adoption:<hash>`，可点名试跑、提交人工标签或与兼容普通标准一起评分。已打开的知识保留原反馈，点名结果可查询调用收据。 |
| `recall maintenance` | 有反馈记录的经验进入预览。置信度低于 0.15，或按原文日期计算超过 180 天且置信度低于 0.30，可显式归档。至少 5 次召回、至多 1 次采纳且涉及至少 2 位召回成员的规则、文档或 Skill 可生成修订草稿；当前发布版本继续生效，审核后切换。 |
| `recall promote` | 展示置信度至少 0.90、至少 5 次正反馈、至少 2 个反馈者且按原文日期计算已满 14 天的候选。向规则、文档或 Skill 提出晋升建议、理由和正文；评审通过后生效，驳回后可重新提议，目标存在时保护原有资产。 |
| `import --dir/--from-repo/--from-org/--from-repo-list` 和 `codebase` | 以授权仓库为输入，确定性提取代码结构，再按需生成模块设计、架构和场景。按源提交增量更新并记录当前、过期、缺失和未知状态；支持状态、校验、补齐、关系调和。 |
| 资源关系 | 规则、文档和经验可在 `related` 中通过团队路径声明 `MAPS_TO`、`REFERENCES`、`SUPERSEDES`、`CONFLICTS_WITH`。经验贡献保留有效声明并返回警告，规则和文档的结构错误出现在审核预览，修正后才能发布。代码图支持 `DEPENDS_ON`、`CONTAINS`、`IMPLEMENTS` 和跨文件调用 `REFERENCES`。发布规则的适用路径唯一命中本项目中的一个代码来源时，双向展示 `MAPS_TO`。正文 Markdown 链接指向同范围内唯一可见的发布条目时，双向展示 `REFERENCES`。一条命中最多显示五条关系，显式关系优先。关系展示沿用项目权限，排序仍由检索分数决定。 |
| CI 从 MR 提取 | 审阅阶段展示建议，合并后发布未被拒绝的知识并增量更新代码知识。代码托管凭据由平台管控，按事件与源版本幂等处理。 |
| `digest` 与知识库健康报告 | 按共享及项目范围查看召回、采纳、冷热、晋升候选和代码来源状态。 |
| 控制台知识库入口 | 工作空间所有者和管理员默认进入健康报告，其他成员默认进入检索。检索页提交非空关键词后才展示跨类型结果。来源页可打开按来源限定的 GitHub 评审经验。Skill 参与检索和报告统计，包和版本在 Skills 管理。 |

## 团队改进与评估报表

四个入口以 TeamAI CLI `1104f305` 的 Dashboard 为交互基线，读取 Weora 已登记且当前身份有权访问的数据。

团队改进与评估设计包含四个页面的桌面和 390 px 窄屏画板，评分器另有工作流评分视图。

| 页面 | 报表契约 |
| --- | --- |
| 改进中心 | `GET /dashboard/improvement` 返回 7、30 或 90 天的团队活动和上期对比。成本以 UTC 请求日归属，没有计价记录显示未知。会话数据以首次 Stop 日归属。Skill 采用情况使用实际记录的最近 30 天，归属以资产为准。维护候选沿用知识健康报告口径。限工作空间所有者和管理员查看。 |

### 工作流评分分组

对照 TeamAI CLI `1104f305` 的 `src/scorers/results.ts`、`src/scorers/label.ts` 和 `docs/guide/zh-CN/dashboard.md`。同一工作流运行、步骤、轮次、评分标准及评审口径的重评使用最新评分时间。阶段判定并入同一标准和运行模式下的模型口径，人工标签独立。评审模型通过率仅取实际评审的样本，阶段判定与来源未知分别汇总。

工作流页提供工具、模型、团队修订、智能体定义、角色、项目、标签、指纹、Skill 和判定阶段十种分组。区分实际报告模型和请求模型、已确认无值和未记录，支持选择分组查看失败标签，每次扩展 25 条，上限 1000 条。原工作流运行以来源 ID、步骤和轮次定位。

所有者和管理员在工作流评分页通过 `POST /dashboard/scorers/workflow/import` 导入 TeamAI 团队报表分支的 `scores/<成员>/<月份>.jsonl`。每次最多 1 MiB、2000 行，记录归入当前工作空间共享范围或明确选中的项目。导入保留评分口径和证据元数据，丢弃报表以外的字段，跳过会话评分。相同记录可重复导入，同一评分时间的判定存在冲突时整批回滚。迁移 `20261124_0103` 保存评分及导入者，有评分时保护回退。

| 验收项 | 结果 |
| --- | --- |
| Figma MCP | 先更新两张工作流画板，再开发。读回并截图检查判定来源、分组、失败明细和窄屏折行。 |

### 团队报表分支自动同步

对照 TeamAI CLI `1104f305` 的 `src/scorers/label-store.ts`。管理员在「工作流评分 → 自动同步设置」为共享范围或单个项目绑定一个已通过连接检查的仓库。项目范围的来源必须登记在本项目，共享范围可明确选择同一工作空间内的来源项目。查看和保存使用 `GET/PUT /dashboard/scorers/workflow/sync`，保存后由后台领取，无需逐文件导入。

- 固定读取 `teamai-reports` 的提交，只解析最近 180 天所涉及月份的 `scores/<成员>/<YYYY-MM>.jsonl` 普通文件。提交相同跳过下载，提交变化时只重新解析 blob 有变更的文件。文件删除和新快照一起发布。
- 生产复用现有仓库同步。配置 `WEORA_REPOSITORY_SYNC_ENABLED=true` 和 `WEORA_REPOSITORY_CACHE_PATH`，Celery Beat 调度到 `weora.repositories.sync`。沿用 `WEORA_REPOSITORY_SYNC_INTERVAL_SECONDS`，默认每个来源五分钟检查一次。
- 临时错误、缺少分支或评分文件无效时保留最后成功的快照并等待下一轮。关闭同步或原仓库连接失效时隐藏该来源的自动评分。连接版本变化后，管理员重新确认来源。手动标签可继续查询，与自动标签按原始评分身份去重。
- 迁移 `20261124_0104` 记录同步来源、租约和最后成功提交。回退会移除可从 Git 重建的缓存和绑定，保留手动导入记录。

| 验收项 | 检查内容 |
| --- | --- |
| Git 读取 | 实际 Git 验证分支缺失、固定提交、相同提交无重拉、只解析变更文件、忽略非报表路径和删除已移除的文件。 |
| 失败恢复 | 拉取失败和损坏文件保留旧快照，下次成功后自动更新。 |
| 并发与范围 | 验证租约互斥、设置版本冲突、停用后在途任务不能发布、共享与项目隔离、普通成员只读及仓库停用撤权。 |
| 控制台 | 用合成 Git 报表验证一次配置后自动显示评分、来源切换、停用和桌面及窄屏布局。 |

## Weora 存储与授权

- PostgreSQL 保存知识条目、不可变正文版本、发布指针、来源引用、变化审计、召回与反馈。控制台、CLI 和 Agent 查询同一服务。
- 共享知识以工作空间为边界。项目知识额外走项目访问检查。代码和飞书来源用原模块的授权读取，检索及关系查询验证目标的作用域。
- 普通贡献、导入选择、修订和晋升各自有独立的状态语义。发布事务同时更新当前版本、审计与可检索状态。推送重试使用工作空间、成员和请求键标识，参数变更返回冲突。
- PostgreSQL 中的版本与来源是可恢复的权威数据。原会话或外部凭据保持在原有领域内。远端索引使用授权连接与固定提交。本地导入使用项目授权和设备提交的内容哈希，平台保存派生证据，不保存绝对路径或源码全文。
- CLI 使用已登录设备身份；Web 使用会话和 CSRF；平台 Agent 由任务绑定的授权主体调用。用户提交的会话标识只用于关联与去重，不能授予读取权限。

## 工程顺序

1. 项目与共享知识、贡献、版本与审计、检索及反馈、维护和晋升的持久化契约。
2. CLI、Agent 使用引导、控制台详情与健康报告，完成真实客户端验收。
3. 接入来源采集和受控工作流，逐条核对导入、续接、代码图谱和 CI 行为。

每个流程分别记录 API、数据库、CLI 和真实来源验证。上游设计条目只有在对应入口可用并验证后才视为完成。

## 后续流程的验收条件

- **会话提炼**。触发信号来自同一根会话的用户纠正、工具拒绝和反复失败；每会话最多提示一次。交互确认前可修改经验、作用域、转录共享与评分选项；无人值守和不可调用分享流程的会话使用 TeamAI 对应的降级行为。转录的脱敏和发布授权独立于经验正文。
- **来源导入**。先授权读取与识别变更，再分类或提炼，最后展示逐条决定。一个来源失败时保留其他来源结果，返回失败项并可恢复。重新导入同一源版本应得到同一结果，私人内容和跳过项不进入共享检索。
- **图谱与新鲜度**。同一仓库用稳定身份区分，记录源提交和文件快照。重复导入只重建变更范围，模块设计生成失败时保留确定性提取的证据。检索中显示当前、过期、缺失和未知，跨项目的关系目标不出现在结果中。
- **CI 与持续改进**。MR 审阅阶段展示提炼建议，合并后处理未拒绝的建议。评分器只评价有权访问的命中，修订和晋升接受前都保留当前发布内容。项目 Skill 继承知识条目的项目范围。已授权设备选择同一活跃项目后，可同步对应版本及提交安装回执。
