# 设置页实施与验收（2026-11-05）

本轮按 Figma 设置 v2（链接已脱敏） 实施设置页、相关入口和弹窗。技术栈沿用 React、HeroUI 3.2.6、React Router、TanStack Query 与 Python 模块化单体；执行授权和审批流程继续复用既有服务。

后续已按用户要求把模型与密钥升级为多厂商、多模型、多 Key 列表，当前实现及生效边界以 [多模型配置验收](model-connections-acceptance-20261105.md) 为准；下文保留首次实施记录。

## 页面与交互

| 页面 | 已接入能力 |
| --- | --- |
| 个人资料 | 名称、头像上传/重新编码/移除/持久化；邮箱按用户决定只读；外观即时切换并沿用 `weora-appearance` |
| 代码 | 团队 Git 署名设置；Codeup 连接与存量配置导入；当前业务空间仓库列表、添加/编辑、独立读取检测 |
| 业务空间 | 新增、切换、名称/介绍/架构/研发约定保存；仓库管理入口 |
| 模型与密钥 | 团队管理员设置 DeepSeek 连接、只写 Key、输出/模型/整体执行预算、显式认证与模型可见性检测 |
| 飞书连接 | 应用与群来源、密钥轮换、读者授权、身份关联、来源集合；高级群路由与接收/投递诊断 |
| Agent 协调 | 既有协调范围选择与新增、模式、暂停、并发、主/Worker 模型和规则；协调状态入口 |

工作台侧栏“设置”和账户齿轮均可进入；设置侧栏提供“返回工作台”。路由、页签、空间切换、弹窗关闭和浏览器离开均覆盖相应的未保存草稿保护。新增协调范围继续从已授权来源和发布资产选择，保留原观察模式默认值。

“业务空间”复用现有 `Project`，没有新增第二套租户模型。`workspace_id` 仍表示团队安全边界，`project_id` 表示业务空间；空间选择保存在按团队和用户隔离的浏览器键中，并与服务端可见列表核对。团队配置单独标示，对团队内业务空间共享。

Git、仓库和飞书编辑器继续保留原有凭据、构建与来源授权字段。普通 Git URL 不依赖托管 API 连接。仓库保存、读取检测、远端写入授权是独立步骤。

## 配置生效与数据保护

- 新增 `console_settings` 模块与迁移 `20261105_0019_console_settings.py`。设置版本追加保存，当前指针通过版本比较更新；并发旧写入返回 409。
- 模型 API Key 使用既有部署加密能力，HTTP 响应仅返回是否存在；新增与轮换的密钥不进入运行快照、日志或浏览器存储。模型探测固定官方主机、禁止重定向、限制响应大小，不发生成请求。
- 新 Run 和新主会话固定模型配置版本。旧 Run、续接及已有主会话继续使用其固定版本；历史无版本运行沿用部署配置。第一次保存继承的部署 Key 时，同样冻结加密版本。
- Git 署名在新任务关联业务空间仓库时冻结，发布器从 Task 的可信快照取值。署名不能由模型工具临时指定，也不会改变仓库、分支或审批范围；兼容的默认测试仓库路径保留既有行为。
- 头像由浏览器缩放为 256px PNG，服务端独立限制编码、尺寸和体积。头像读取需要当前登录会话，使用私有且禁止缓存的响应。
- 模型与全局 Git 写入需要团队所有者/管理员；业务空间和仓库继续使用原有权限规则。写接口沿用 Cookie + CSRF。
- 复查后，模型连接与运行预算改为分别保存，复用同一个带版本校验的后端接口；一块表单不能夹带另一块的未保存草稿或密钥。认证探测仅证明服务端认证与模型可见性，实际执行还需要当前 Pi SDK 支持该模型，并满足部署执行开关和任务授权。

## 实际浏览器验收

使用独立 SQLite 验收数据启动完整 FastAPI 与 Rsbuild 页面，未启动飞书接收器或模型 Worker。真实页面验证了资料和头像保存、刷新恢复、业务空间新增/切换与仓库隔离、仓库保存、模型预算保存、未保存提醒、弹窗关闭与重新打开。模型和飞书外部服务采用自动测试的脚本响应验证，没有使用真实账户密钥发起外部联调。

六页均在 1440×1000、390×844 的深浅色中采集；整页无横向溢出，表格在自身容器滚动。字体沿用项目系统字体栈，没有把 Figma 缺失字体时的 Noto Sans SC 替代字体引入应用。按钮、输入、选择器、开关、标签和弹窗使用 HeroUI；业务 CSS 只补充布局和间距。
