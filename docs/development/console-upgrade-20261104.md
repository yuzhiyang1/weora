更新时间：2026-11-04。用户已选择“全部控制台统一升级”，并明确顺序：**先梳理计划，在 Figma 创建项目并出设计稿，用户审核通过后才改造应用。**

当前阶段：规划与设计。此前“实施中”的表述作废。本任务书描述待设计内容，不代表界面已实现或已通过验收。

目标：内测用户能看懂任务正在做什么、哪里需要自己处理、结果在哪里；管理员能管理主 Agent、执行会话和接入配置。

沿用 React、HeroUI v3、现有 API、权限、发布版本与审批机制。RAG、长期记忆、工作流、协作室不纳入本轮功能开发；规划入口降为次级。设计以现有代码为准，所需接口缺口单独标注，不把设计稿当成能力已实现。

## 设计方向

以任务与下一步操作为主，保留 HeroUI 默认主题、系统字体、Lucide 与浅深色。改善信息结构和密度，不引入第二套控件或营销风格装饰。加载、空、失败、权限不足和提交中分别呈现，不以示例数据冒充业务状态。

| 页面范围 | 当前问题 | 设计要求 |
| --- | --- | --- |
| 外壳与导航 | 可用功能和规划入口混排，重复主入口，技术词过多 | 明确工作/资产/连接分组；规划入口降为次级；统一标题、位置与快捷导航 |
| 工作台 | 资产计数占据首屏，任务目标和待办不突出 | 待处理与近期任务优先，紧凑真实计数，明确下一步 |
| 任务列表与详情 | Agent 名和 ID 主导，输出像日志，续接入口缺失 | 任务目标预览须经过正文授权；清楚的进展与操作；接入现有私有任务续接 |
| 协调中心 | 多个范围、任务与诊断混在一处 | 范围选择、任务状态、政策与诊断分层，保持 revision CAS |
| Agent / Skills | 重复说明、筛选与主操作不统一 | 统一列表、搜索、发布状态、详情及编辑表单的层级 |
| 项目与代码设置 | 连接、仓库、项目授权的关系难理解 | 对应领域分区、明确状态与就近操作，保持凭据只写与权限边界 |
| 飞书上下文 | 一个长页面堆叠连接、来源、授权、身份和路由表单 | 按设置步骤分区，创建/修改按需展开，诊断不挤占日常操作 |
| 登录 / 规划 / 异常 | 工程说明和占位感较强 | 统一产品文案、返回路径和真实可用入口，不伪装未实现功能 |

## 信息架构提案

以下为待评审的导航，不要求改变现有路由或模块归属。

| 分组 | 入口 | 约束 |
| --- | --- | --- |
| 工作 | 工作台、任务与运行、协调中心 | 协调管理按角色展示，直达链接仍校验权限 |
| 团队能力 | 项目、Agents、Skills | 区分项目范围、固定版本与可复用能力 |
| 连接与设置 | 飞书、代码连接 | 连接不等于读取/执行授权，配置与诊断分层 |
| 次级入口 | 规划能力、账户、主题、快捷查找 | 不伪装未开发功能，不虚构工作空间切换 |

同一个 Task 可以有多轮 Run。当前若按 Run 返回列表，设计不能把运行条数称为任务总数，也不能虚构任务级聚合。

## 五条评审流程

1. 个人任务：工作台 → 创建 → 确认版本与范围 → 查看进展和结果 → 补充要求 → 等待或进入下一轮。
2. 飞书自动协调：选择范围 → 未 @ 候选判断 → 接单与 Worker → 运行详情 → 原线程跟进。观察模式只记录，自动模式仍遵守权限。
3. 审批：待办 → 目标与差异 → 同意/拒绝 → 反馈与交付；代码变化后重新审批。
4. 发布能力：编辑 Agent → 绑定 Skill 固定版本 → 发布 → 发起任务。
5. 管理员接入：连接 → 仓库/来源 → 项目范围或身份授权 → 执行入口 → 实际连通/接收诊断。

原型连接标注角色、服务端状态、返回位置与确认条件。飞书仍是现有主要交互入口之一，本轮不擅自引入新 Web 主 Agent 聊天协议。

## 状态与权限矩阵

| 场景 | 必须单独设计的状态 |
| --- | --- |
| 读取 | 加载、有数据、首次空、无结果、失败重试、无权限、资源失效 |
| 表单 | 初始、校验失败、无候选、提交中、失败保留输入、结果未知、成功可再次使用 |
| 运行 | 排队、执行、待上下文/人类、待审批、成功、失败、取消、可恢复；逐项核对实际枚举 |
| 后续消息 | 已接收待处理、等待当前轮次、已关联下一轮；接收不表示模型已读或完成 |
| 协调 | 未配置、显式请求、观察、自动、暂停、停用、并发受限、人类待办、版本冲突 |
| 连接授权 | 未配置、保存但未验证、探测通过/失败、授权不足/撤销；保存不等于连通 |
| 角色与正文 | Owner/Admin 配置权限、普通成员入口、私有正文不可见、权限失效后隐藏正文 |

设计使用合成数据，不带真实群消息、密钥、用户身份或私密仓库内容；统计标明全量还是当前加载范围。

## 设计与接口的差异

- 运行列表目标预览：当前摘要以元数据为主。若采用正文预览，改造阶段需补授权投影与撤权缓存处理，不直接放开正文。
- 私有续接：已有后端接口，前端待接入。回执区分排队/新 Run，保留幂等语义。
- 群任务续接：沿来源路由处理，不复用私有接口绕过协调绑定。
- 搜索与统计：标明本地已加载过滤、现有服务端查询或待补接口；不虚构全量能力。
- 新 Web 聊天、即时插话等超出现有协议的内容，单列范围，不混入外观改造。

设计标注统一区分“已有能力 / 前端待接入 / 需要接口调整”，并对应后续实施清单。
