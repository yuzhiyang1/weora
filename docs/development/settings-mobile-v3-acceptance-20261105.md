## 实施边界与代码组织

- `SettingsMobileNavigation` 复用 AppShell 的栏目定义和现有 `BusinessSpacePicker`，直接提供返回工作台、当前空间和栏目选择；没有另建菜单数据或状态存储。
- 路由与空间切换继续使用 `SettingsEnvironment` 的草稿保护；手机抽屉打开空间选择器前先关闭，避免两个导航层同时争夺焦点。
- 仓库/飞书列表使用同一份 HeroUI Table DOM，列定义提供手机标签；模型列表保留已有专用响应式布局，没有渲染两套操作按钮。
- 手机样式只处理布局、间距、长标识换行和安全区留白；按钮、输入、选择器、弹窗及焦点行为继续由 HeroUI 提供。
- 无后端、数据库、审批、鉴权或执行器改动。业务空间仍复用 Project，团队身份仍为 workspace_id。
- 运行预算仍可分别留空，沿用保存时部署默认值；已有任务的冻结版本保持不变，不因切换 Key 改写。
- 代码质量审查修正：模型重试开始时撤销旧成功标记，失败明确显示“检测失败”；设置页停用应用和读者撤权需确认，失败保持弹窗并可重试。

修复的真实布局问题：

1. Dialog 与 Body 双重内边距挤压手机长表单：移除重复留白，保留 HeroUI 的焦点环空间。
2. 无自然断点的协调范围标识把 320px 页面撑至 523px：限制 Select 值的 flex 最小宽度并允许断行。
3. 手机卡片留白被后加载桌面规则覆盖：将 16px 手机规则放回同一设置样式文件。
4. 身份表单使用 agent-form，原断点仅匹配 context-form：补充身份表单匹配，手机改为单列。

截图、布局 JSON、Figma manifest 与虚构数据准备脚本位于 `output/playwright/settings-mobile-20261105/`。完整图片使用 `*-full.png`、`*-final-full.png` 和 `*-320-final.png`；部分 viewport 截图受浏览器截图缩放影响，视觉核对以完整长截图为准。

## 后续原生 App 的明确验收项

本轮交付手机 Web 与可复用的移动交互设计，没有新增原生 App 空壳，也不要求原生复用 Web CSS。原生实现应复用领域/API 契约，使用其平台组件落地。

以下必须在真实 iOS/Android 上验证，不能用桌面缩短视口代替：系统返回/返回手势与草稿保护、真实软键盘和可视视口、刘海/底部手势区域、文件/相册权限与上传取消、系统深浅模式与本地偏好、后台恢复与网络中断、登录态安全存储、屏幕阅读器、文字放大及平台触摸目标。390×460 仅证明短视口下内容和操作可达，不代表已完成软键盘实机测试。
