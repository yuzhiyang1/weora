## 2. 代码入口

- Console：`apps/web/src/features/runs/`、`features/context/`；复用现有 Semi 设计与公共样式，没有复制 Multica 源码。
- 运行：`backend/src/weora/modules/runs/`，任务归属仍在 `modules/collaboration/`，通过应用接口参与同一事务。
- 工具：`modules/tools/`；模型只提交工具名与业务参数，不能提交 Actor、密钥、连接、审批主体或 fencing。
- 飞书：`modules/context/`；Reader、权限、快照、预算与渠道职责分开。SDK只做长连接运输，历史只有一种HTTP适配器。
- 交付：`modules/delivery/`；人工审批、Docker、浏览器、GitHub代理、事实完成门槛和派生产物。
- 装配与后台：`bootstrap/application.py`、`execution_services.py`、`worker.py`、`feishu_receiver.py`、`retention.py`。
- Pi：`runtimes/pi/`；精确固定 Agent Core/pi-ai 1.3.0，不安装个人会话或Coding CLI扩展。供应商函数名按其限制在适配层映射，业务工具名和审计不变。
- 沙箱镜像模板与本地验收脚本：`runtimes/sandbox/`；WSL Docker已安装，真实容器与完整浏览器镜像的验证范围见最新联调记录，不与原实施快照混淆。

## 3. 关键安全与恢复边界

### 平台、Agent、Tool

平台决定身份、受众、连接凭据、来源授权、稳定截止点、预算、快照、审批和持久化状态。Agent决定查哪个来源、什么窗口、是否翻页/展开、怎样提出计划。Tool只执行明确参数与授权内动作。角色切换由Worker决定，不能从模型参数获得更高权限。

Pi工具循环通过自有JSONL协议请求Gateway；没有原始shell、任意URL或个人账号回退。真实改码和浏览器在Docker内执行，Pi文本子进程本身不冒充OS级沙箱。

### 事实而不是模型自报

研发完成需要同一计划版本的真实写入、修改后的验证命令/退出码、当前非空Diff，以及计划声明的浏览器/PR事实。产物具有每Run单调序号，不能因为Windows时钟同一tick而复用旧测试。命令证据还需绑定执行前后相同的仓库状态摘要，并与最终Diff匹配；命令本身改码、格式化或生成文件后，旧测试不能证明新代码通过。咨询与只读历史查询没有改码证据要求。

### 身份、授权与受众

群消息作者可以是未绑定外部参与者，但发起历史读取的主体必须是明确绑定的有效成员。群Run固定原群，私有多来源结果没有转群入口。来源撤权、连接禁用或成员解绑后，Run正文、工具缓存、计划、产物、快照、恢复和通知均重新鉴权；客户端也持续复验已展示终态。

### 崩溃与未知结果

Redis只通知，PostgreSQL保存权威状态。审批投影、提交Run后Inbox回写前中断、结果提交后Outbox入队前中断都有幂等补偿。已批准的执行中断不自动重启；人工恢复仅恢复只读分析，并在数据库持续禁止写。未知PR只读核对，飞书发送未知结果保留待核对，不承诺首版可自动消除每种未知状态。

### 正文保留与清理

来源正文默认7天（可缩短），到期先拒绝访问，再清快照、Run输出、Task正文、工具参数/结果、计划与产物和渠道副本，保留审计摘要。运行中失效租约不能重新写回过期正文。已送给模型或飞书的内容无法保证远端召回。

Worker finally清理本实例环境；Beat只回收同部署、有完整所有权标签、且无有效Run租约的容器，并按不可变ID删除。不清理其他部署、未知Run或任意宿主文件。
