## 1. 复现与修复

### 1.1 Worker 硬退出后工具永久显示 RUNNING

独立 Python 进程执行生产 `RunExecutor` 和 `ToolGateway`，使用真实 PostgreSQL 随机 schema；确定性 Runtime 只用于命中故障窗口，不冒充真实模型。第一项工具已提交成功，第二项工具的效果已持久化、但调用结果尚未返回时，父测试直接强杀进程，跳过 `finally`。

修复前：租约自然过期后 Run 为 `RECOVERY_REQUIRED`，但第二项工具仍为 `RUNNING`。回归测试先观察到失败，再实施修复。

修复：

- 新工具调用保存 `lease_owner`、`fencing_token`，与原执行尝试绑定。
- Beat 调度阶段按原尝试复核租约，将失效尝试的在途工具转为 `UNKNOWN / TOOL_INTERRUPTED`。
- 不重放工具，不覆盖成功事实；迟到完成不能覆盖 `UNKNOWN`。
- 新租约中的活跃只读调用不被旧尝试的补偿误伤。
- 旧记录的新增字段可空；不猜测旧 owner，等整个 Run 不活跃后才补偿。

迁移为 `20261019_0012`，原有工具调用、预算、复合主键与幂等键均保留。

### 1.2 渠道正文过期后，清理前仍能读派生内容

真实 PostgreSQL 中，仅将本例 Inbox 或 Outbox 的正文保留期推进到过去，快照仍有效，且尚未运行物理清理。修复前，Run 正文仍返回 HTTP 200。

修复：群 Run 的每次上下文范围校验同时检查其 Inbox、Outbox 保留期；到期立即拒绝正文、快照、工具结果、产物、计划、恢复与通知，不等 Beat 删除副本。后台清理仍可幂等重试。

注意：Run/Tools 隐藏入口返回 404，Context/Delivery 已有接口可返回带 `CONTEXT_EXPIRED` 的 409；两者都不能返回正文。无正文的审计事件按用户权限保留，不把保留审计误判为泄露正文。成员停用还会使认证失效，返回 401。

### 1.3 引用与话题串行读取无谓耗尽自动补齐预算

测试中两个独立只读请求各耗时 1.6 秒，原串行实现超过 3 秒后返回 `partial / timeout`。修复后并发读取，仍共用原 3 秒总预算，引用优先、消息数量、Token 预算、截止点及授权规则均不变；引用不会因为网络返回较慢而失去优先级。

这项修复不保证上游永不超时。真实飞书首次获取应用凭证曾接近 2.5 秒，加上消息读取仍可能超过上限；此时保守等待是预期行为，不能把失败快照改成完整。

### 1.4 补充脱敏渠道诊断

此前 SDK 日志都压成一个错误码，无法区分连接失败、接收循环退出和事件处理失败。现在仅按 SDK 固定前缀输出自有代码：

- `FEISHU_CONNECT_ERROR`、`FEISHU_RECEIVE_LOOP_ERROR`、`FEISHU_EVENT_HANDLER_ERROR`、`FEISHU_PING_ERROR`。
- `FEISHU_CHANNEL_CONNECTED`、`FEISHU_CHANNEL_DISCONNECTED`、`FEISHU_CHANNEL_RECONNECTING`。

不输出握手 URL、凭据、事件正文或供应商异常栈；未提高原始 SDK 日志暴露范围。2026-10-19 18:19:52 实际接收进程输出 `FEISHU_CHANNEL_CONNECTED`，这只证明已连接，不等于每条用户消息都已入站。
