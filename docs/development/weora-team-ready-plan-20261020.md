# 第一版收尾与团队自助配置

基线：`0fc6eda`，沿用已重构的 shadcn/ui，不恢复 Semi，不复制 Multica 源码或品牌。
参考材料仅为用户提供的设置页截图；借鉴代码托管、仓库列表、交付规则分层，不推断未展示的产品能力。

## 实施顺序

1. 代码配置：工作空间 MR API 连接与项目 Git 仓库分离；只写密钥、版本 CAS、同组织关联、停用撤权。
2. 构建配置：从部署管理员预置镜像中选择，保存 argv 建议并冻结到任务；不允许任意镜像或宿主路径。
3. 设置交互：代码源页统一查看连接、项目仓库和交付边界；复用现有项目表单与组件，保留多仓最小选择。
4. 飞书诊断：独立显示接收进程、连接生命周期、供应商事件、唯一 Inbox、Run 和回复；不把人工补收记为自动入口。
5. 普通 Agent：经用户选择使用本机隔离仓库的小 Bug，不改业务仓库，不预置答案路径，不自动合并或部署。
6. 验证：接口权限、秘密与版本失效回归；真实页面桌面/窄屏；隔离仓库真实模型、审批、容器测试。

## 验收与边界

- 代码源配置不把 Git 密码当作 MR API 令牌；已保存不等于远端验证通过。
- MR API 连接变更、清除或停用后，旧任务不能继续使用旧批准写远端；旧部署连接兼容保留。
- 保存构建建议不会执行命令。每次文件修改、命令、分支和 MR 仍必须符合有效审批。
- 日志和原始测试报告的受控留存需单独验证；仅保存摘要不宣称已保留完整构建证据。
- 飞书上游未投递时，不伪造供应商事件，不无限催发；记录有界诊断和外部缺口。
- 本轮不擅自提交、推送、合并或部署；不修改用户已有的前端重构提交。

## 本轮结果（2026-10-20）

### 已完成

- `/settings/code`：工作空间代码源、跨项目仓库总览、搜索、Git 校验、先选项目再添加仓库；沿用现有 shadcn/ui，实测桌面、390px 窄屏及深色模式。
- 项目仓库可保存预置构建环境与 argv 建议、显式关联云效 MR API 连接；任务冻结环境指纹和身份版本。Git 凭据与 MR API 身份独立，密钥不回填，停用/轮换使旧任务失效。
- 飞书接收诊断：独立显示进程心跳、连接状态、PONG、业务帧、供应商事件和 Inbox/Run；支持输入消息 ID 核对最近本地记录，不把人工补收记作自动入口。
- 普通研发 Agent 已在本机隔离仓库完成 Console 发起、模型自主读码、计划审批、真实容器失败回归、修复、通过测试和 Diff。未使用预设文件名或修复答案的验收助手，未动业务仓库。
- 真实验收修复两处问题：审批工具缺失合法动作枚举；工具调用拿到回执时，命令失败结果容易被“调用成功”掩盖。现在 schema 明确审批权限与 Tool 的映射，前端额外标记命令退出码。

### 尚未通过或未覆盖

- 飞书自动入口仍未通过：用户 18:20 发送的真实 @ 文本可由飞书历史 API 确认，但未进入本机供应商事件记录和 Inbox。连接有 PONG、无业务帧；只能确认当前接收端未观测到该事件，不能断言具体上游原因或存在其他客户端。未人工补收，未催发新消息，未把替代入口算成功。
- 新数据库代码源的真实外部云效 MR 尚未创建；本轮覆盖本地持久化、权限、版本失效、只读仓库映射和适配器回归，不冒用以往部署级 MR 的证据。
- 当前只开放管理员预置的构建镜像。通用私服秘密自助管理、任意 JDK 配置、完整原始构建日志/产物保留策略仍是后续独立任务。
- 普通 Agent 额外增加了非必要的 unittest `__main__` 入口，仍在批准路径内且最终报告明确承认；核心链路通过不代表补丁已经达到严格最小改动的质量标准。验收保留原始 Diff，不事后改写证据。
