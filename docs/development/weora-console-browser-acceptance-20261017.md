## 1. 实际操作与结果

1. 打开 `/login`，使用错误测试密码登录：停留在登录页，显示“邮箱或密码不正确”。再使用本机测试账户的正确密码登录成功。
2. 从导航进入“运行”，点击“发起任务”；未选择 Agent/版本、未填写目标时，提交按钮禁用。
3. 选择 `Console Connectivity Agent` 和不可变版本 `0.1.0`，输入“请只回复：Weora 前端验收成功。不调用工具。”，点击提交。没有用 API 脚本替代此次页面提交。
4. 自动进入任务详情，先看到排队和“尚无回答”；随后自动显示“执行成功”、模型名称和真实回答“**Weora 前端验收成功。**”，事件补齐 `run.queued / run.started / run.succeeded`。
5. 刷新页面，任务、回答及 3 条事件保留，终态不再展示取消按钮。
6. 点击退出登录，再输入正确密码登录。修复路由竞争后，稳定回到原任务；等待下一次成功的详情 GET 后仍停留原任务，不再被导航回首页。
7. 检查桌面 `1440×1000` 与窄屏 `390×844`；窄屏文档宽度等于 390，无横向溢出，8 个导航图标的实际宽度均为 16px。
8. 飞书未配置时显示信息提示，不展示不可用查询表单；跨越原轮询周期后，快照请求计数保持不变。点击“刷新授权来源”可显式重试，模型回答仍显示。
9. 首页静态资产已明确标注为示例，固定进度条已移除，未实现的聚合按钮显式禁用。没有实现或宣称新增实时资产聚合能力。

## 2. 发现并修复的问题

| 问题 | 原因与修复 | 验证 |
| --- | --- | --- |
| 登录提示仍称密码任意输入 | 提示写死为开发绕过，实际后端已关闭绕过；改为真实账户密码提示 | 错误密码拒绝、正确密码通过、登录页截图与组件回归 |
| 重登后跳回任务又跳到首页 | 表单导航与 `GuestOnly` 的 `/` 导航竞争；改由守卫统一读取受保护页来源，拒绝外站与认证页循环目标 | 先复现组件测试失败；修复后自动测试通过，真实页面退出/重登并等待后续详情请求后仍停留原任务 |
| 窄屏导航图标消失 | CSS 隐藏所有 span，误伤 Semi 图标；只隐藏导航文字，并补导航名称与 title | 窄屏截图和实际 DOM 尺寸检查 |
| 飞书未配置仍持续请求 503 | 未区分部署未启用与暂时网络故障；遇到 `CONTEXT_NOT_CONFIGURED` 停止轮询/聚焦自动刷新，显示信息态并保留手动刷新 | 假时钟跨 30 秒不新增请求；真实网络请求计数不再增长；实际点击手动刷新 |
| 运行详情缺少卡片边界与间距 | `.detail-card.semi-card` 不匹配运行页的语义 section；在运行页作用域复用 Agent 详情的色值、边框、圆角和阴影 | 与现有 Agent 详情真实截图对比，桌面/窄屏截图复核 |
| 首页示例冒充实时进度和动态 | 固定 `01/04`、固定示例名称和时间未标明性质；改为使用指南、明确示例资产，禁用未实现的聚合操作 | 组件断言与真实页面检查，进度条数为 0 |

没有把未登录 `/auth/me` 401、故意错误密码的 401 或首次检测飞书未配置的 503 称为页面崩溃。首次两次上下文请求仍会真实返回 503，前端不会伪造成功；后续自动轮询已停止。没有发现本流程中的未处理 JavaScript 异常。测试仍有 Semi 依赖的既有 `findDOMNode` 弃用警告，本轮未为此升级组件库。
