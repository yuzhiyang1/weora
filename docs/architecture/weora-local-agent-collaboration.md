## 1. 功能边界

前端开发者在自己的 Codex 会话里说「和后端 Agent 联调订单分页」。Codex 找到已接入这项任务的后端 Claude Code 会话，发出失败请求。后端 Agent 在原会话里利用已有调查和本地代码查证，回复接口约定和测试环境版本。前端复测后发布结果。Weora 任务详情展示这次联调的消息、投递状态和显式发布的证据。

以 **Task** 限定联调范围，以 **原生会话绑定** 指定收发端。每个 Task 最多一个联调线程，同一任务可有多个成员和会话。开发者继续使用自己的客户端、模型账户、仓库和原生审批。联调消息在本地 Agent 之间交换，平台不为这些消息创建 Celery Run。接入任务也不授予原始 Task 正文、私有 Run、飞书来源、仓库凭据或本地终端的访问权。

| 设计稿入口 | 预期行为 |
| --- | --- |
| 接入本地会话 | 复制任务加入指令，在当前原生会话发起加入，由会话所有者确认 |
| 查看可对话会话 | 在任务详情的「已接入会话」区域打开目录，查看自己有权联系的同事会话、归属、仓库与在线状态 |
| 复制对话指令 | 选中目标后，将带任务和目标会话引用的示例指令粘贴到自己的已接入会话，由本地 Agent 发送 |
| 联调消息 | 按服务端顺序显示发件会话、收件会话、回复关系、状态和附件 |
| 投递详情 | 区分 Weora 已保存、目标会话已领取、Agent 已回复及结果待确认 |
| 共享证据 | 读取主动发布的摘录、契约和测试记录，可核对来源版本及受众 |
| 接入记录 | 查看加入、离开、撤权和发布记录，当前连接状态另行显示 |

### 从页面发起一次对话

以周琪的后端 Claude Code 和林晨的前端 Codex 为例。两人先成为同一协作任务的参与者，各自在任务页点「接入本地会话」，将加入指令粘贴到要共享的原会话并确认。随后，周琪在任务页点「查看可对话会话」，选中「前端 Codex · 林晨」，复制发问指令到自己的 Claude Code。也可以直接告诉已接入的 Claude Code「用 Weora 查找 WE-128 的前端 Codex，问它首屏失败的请求、响应和测试环境」。

浏览器生成的指令仅包含任务和目标绑定引用，发件身份由调用时的本地会话确定，发送时复验双方权限。若发现多条匹配会话，提示选择具体会话。未开放的会话不出现在目录里，页面可以提示把任务链接交给同事，请对方自行接入。已开放的目标暂时离线时，问题留在 Weora，等原会话上线领取。对话授权覆盖消息与任务内已发布证据，其他历史保留在原会话。

### 在本地会话直接发问

临时问题可以从原生会话发起。发件人在自己的 Codex 里说「用 Weora 找林晨的前端 Codex，问它订单列表首屏的 cursor 是省略还是传空串」。Weora 按同一工作空间内的成员及会话名称查找，只返回该发件人有权联系的会话。命中多个会话时，由发件人选定收件会话。

收件人对一条原生会话启用「允许直接联系」，并选择可以联系它的工作空间成员。发件人使用已连接 Weora 的设备和当前原生会话发送，当前会话在这次问答中可接收关联回复。平台在查找、发送、领取和回复时复验授权，按具体会话投递并复用原有通知、领取及唤醒机制。对话权限只覆盖这次交换的消息，原生历史和任务证据沿用各自权限。

直接发问不要求 Task，服务端保存参与双方、收发会话引用及消息关联。下文带 `task_id` 的接口和任务证据规则适用于协作任务内的联调。

## 2. 模块与部署

| 模块 | 职责 |
| --- | --- |
| `identity` | 复用工作空间成员和 Web 登录，新增设备登记、设备凭据及撤销 |
| `collaboration` | 复用 Task 协作授权，新增线程、会话绑定、消息、领取、发布证据和审计用例 |
| `projects` | 提供当前项目及任务所选仓库的有效性判断。应用层通过查询端口读取，不跨模块操作 ORM |
| FastAPI 与 PostgreSQL | HTTP 提交、查询和领取。PostgreSQL 是消息与状态的权威来源。WSS 只发待领取或状态变化信号 |
| `apps/cli` | Python 3.12 CLI 与 Skill 提供接入、查找、发问、领取、回复和发布。独立的 Python 常驻连接器维护出站连接与本机适配器，可随 CLI 包安装 |
| `apps/web` | 在现有协作任务详情增加联调页签。复用 HeroUI、查询缓存和任务页面的访问失败处理 |

连接器与 Weora 之间使用 HTTPS 和 WSS，设备向外建立连接。本地进程通过受限 IPC 与连接器交互。会话在线状态和本地唤醒调度可以放内存，重启后从原生客户端和平台重建。**本地不引入 SQLite。** 设备凭据交给系统凭据存储。本机离线时由服务端保存待领取消息，Weora 不可达时领取和提交回复暂停，尚未成功提交的回复不承诺在连接器崩溃后自动补发。

部署多个 API 实例时，提交事务成功后可沿用 Redis 通知模式，唤醒持有连接的实例。Redis 或 WSS 通知丢失时，连接器重连与有界定期查询都会补取。任务页可以沿用现有 SSE 提醒客户端重新查询的方式。

## 3. 设备、会话和授权

1. **登记设备。** 借鉴设备授权流程。连接器显示短码和 Weora 登录地址，用户用现有 Web 会话确认账号、工作空间和设备。短码限时、限频、一次使用，连接器持有独立的高熵兑换码。服务端签发仅用于本地协作的短期访问凭据与可撤销续期凭据。浏览器 Cookie 和设备凭据走各自的入口，授权确认用现有 CSRF 保护。凭据不出现在加入指令、提示词和 WSS URL 中。
2. **加入任务。** 用户在原生会话运行候选命令 `weora collab join <task_id>`。连接器通过原生事件或已验证的本地适配器确认实际会话与配置实例。所有者明确确认绑定和共享范围。可用原生用户确认机制就地完成，无法确认时使用已登录的 Weora 授权页。任务 ID 只用于定位目标。
3. **绑定原会话。** 平台生成稳定的 `binding_id`，关联任务、设备与原生会话。原生会话以 `device_id + harness + profile_id + native_session_id` 区分。配置实例 ID 是不透明标识，本机绝对路径保留在本机。同一个任务和原生会话只能有一条有效绑定。会话恢复仍绑定原 ID，清空、分叉或切换账号产生的新会话需要重新确认。设备在线与会话已就绪分别记录。
4. **执行时复验。** 查找、发送、领取、回复和下载均校验活动工作空间成员、Task 所有者或显式参与者、当前项目与所选仓库仍有效，以及动作对应的会话和设备权限。浏览器按用户查任务范围的公开联调材料。本地凭据只允许受限的协作调用，领取和回复必须来自目标绑定。没有项目上下文的旧任务，需明确补齐项目及仓库关系才能启用联调。

Task 现有 `project_context` 是运行资料快照。联调线程以服务端从该快照解析并复验的 `project_id` 为准。仓库登记目前按工作空间共享，联调采用现有 Task 参与者范围，项目可读不会自动扩大线程受众。已接入会话的展示名称、仓库、分支和工作摘要按白名单上报。未加入、无法辨识或只有同一目录匹配的会话不能成为投递目标。

撤销成员、设备或绑定时，平台拒绝新的领取、回复和下载，待领取消息停止交付。WSS 可尽快下发失效信号，HTTP 在实际操作时始终复验。已经进入 Agent 上下文或下载到客户端的内容无法召回。同一操作与撤权并发时，以数据库事务的授权次序为准。用户设备是本机信任边界，原生会话绑定不提供同一操作系统账户下的进程级安全隔离。

[设备授权流程参考 RFC 8628](https://www.rfc-editor.org/rfc/rfc8628.html) · [现有任务数据模型](../../backend/src/weora/modules/collaboration/infrastructure/tasks.py)

## 4. 数据模型

下表是待实施的逻辑模型。复用现有用户、成员、项目、仓库和 Task 主键。跨表关联带工作空间作用域，任务与项目的关系由应用服务验证后固化。

| 记录 | 关键字段与约束 |
| --- | --- |
| 设备与凭据 | `device_id, workspace_id, user_id, credential_version, revoked_at`。凭据可单独撤销，服务端仅保存校验所需信息 |
| 联调线程 | `thread_id, workspace_id, task_id, project_id, state, sequence, expires_at`。同一工作空间、任务唯一 |
| 原生会话与任务绑定 | 原生会话保存 `device_id, harness, profile_id, native_session_id`；绑定保存 `binding_id, thread_id, native_session_key, state, revision`。一个原生会话任一时刻只处理一条联调请求 |
| 联调消息 | `message_id, thread_id, sequence, sender_binding_id, recipient_binding_id, kind, body, reply_to, idempotency_key, request_hash, created_at, expires_at`。`(thread_id, sequence)` 和 `(sender_binding_id, idempotency_key)` 唯一。同键不同内容返回冲突 |
| 投递与领取 | 目标绑定、状态、领取请求 ID、领取回执、连接器可观测事件和各状态时间。一个消息只有一条权威投递记录，唤醒尝试可有多次 |
| 共享证据 | `evidence_id, thread_id, publisher_id, source_ref, source_version, content_hash, object_ref, audience, revoked_at`。受众限定该任务参与者，版本更新新建记录 |
| 审计 | 记录加入、撤权、领取、回复、发布及人工处理等事实。包含操作者、目标、`request_id`、`workspace_id`、`thread_id` 和适用的 `message_id`，避免记录原始正文和敏感信息 |

## 5. 消息协议与可靠性

### 从发送到回复

1. **发送。** Agent 使用绑定的发件身份提交目标 `binding_id`、内容和幂等键。服务端校验双方归属和线程状态，在同一事务内分配线程序号，写入消息、待领取记录与审计。提交成功即返回 `message_id`。目标离线时仍可受理，显示等待上线。
2. **通知。** 提交后发 WSS 信号，连接器合并同一会话的连续通知，按能力唤醒原会话或在下一个安全时机提示。唤醒提示只带任务与收件提示，不把同事的正文当作本机用户命令注入。重连后主动查待处理记录，重复信号可以合并。
3. **领取。** 目标 Agent 调用领取工具。服务端锁定目标原生会话及投递记录，校验绑定和授权，条件更新 `PENDING → CLAIMED`，写入领取回执后返回正文。客户端为一次领取生成请求 ID，同一请求重试只返回原领取结果，不分配新消息。多窗口、多进程或重复唤醒并发时，同一原生会话只允许一条未结束的领取。取件成功说明平台记录了领取，不能从 HTTP 成功推断 Agent 已完成工作。
4. **回复或确认。** 问题由目标会话提交带 `reply_to` 的回复，服务端在同一事务中保存回复并推进原消息状态。单向通知由目标显式确认，避免每条消息都触发互相回复。回复工具回执丢失可用相同幂等键恢复结果。终止线程后停止接受新的协作消息。

消息正文和证据作为外部输入提供给本地 Agent。工具调用仍受原生沙箱、用户批准与仓库权限约束。连接器只处理预先定义的协作动作，协议不提供远端 shell、键盘注入或审批代理。

### 状态与故障语义

| 持久状态 | UI 表达与处理 |
| --- | --- |
| `PENDING` | Weora 已保存。结合目标就绪状态显示「待领取」或「等待上线」。WSS 已发送、原生队列已接收提示都属于投递事件 |
| `CLAIMED` | 目标会话已领取，仍在处理。会话断开不释放处理权。相同领取请求 ID 可重取原结果，直到确认、回复或授权失效 |
| `REPLIED` / `ACKNOWLEDGED` | 已收到关联回复 / 单向通知已确认。两者均结束本次处理 |
| `NEEDS_CONFIRMATION` | 领取后超时或结果不明。禁止自动把同一条消息重新分配给另一轮。允许原绑定在授权仍有效时补交同一请求的回复，或由用户显式结束、发送一条带前序引用的新消息 |
| `CANCELLED` / `EXPIRED` | 用户停止、任务关闭、授权撤销或待领消息过期，平台拒绝继续领取 |

示例故障：后端 Agent 已领取消息，连接器在回传前断线。Weora 重连后保留原领取记录。领取仍有效时，相同请求 ID 返回原结果。超时后展示「待确认」，原绑定仍可补交回复或由用户结束处理。对需要直接注入正文的适配器，只有能证实未交付、或原生接口支持稳定消息 ID 去重时才可自动重试。

平台可以保证收件和领取的逻辑去重。Agent 修改代码、发版或执行外部命令的效果不受 PostgreSQL 事务控制，这类操作仍使用原生审批及工具自身的幂等或人工确认机制。

## 6. API 与客户端契约

以下接口名用于评审。任务联调接口以 `/api/v1/workspaces/{workspace_id}/tasks/{task_id}/agent-collaboration` 为相对根。

| 接口 | 用途 |
| --- | --- |
| `GET /`、`GET /messages?after=` | Console 读取当前线程、会话状态及按序号分页的联调消息 |
| `GET /sessions` | Console 与 Agent 查询当前用户可联系的目标会话，返回稳定绑定引用和可展示状态 |
| `POST /bindings`、`DELETE /bindings/{binding_id}` | 加入或离开。撤销他人绑定需任务管理权限 |
| `POST /messages` | 发送提问、回复或单向通知。回复须引用同线程原消息 |
| `GET /bindings/{binding_id}/pending` | 按目标绑定补查待领取信号和需核对状态。信号只包含消息引用和顺序 |
| `POST /bindings/{binding_id}/claims` | 领取下一条消息。请求带稳定的领取请求 ID，返回正文及处理关联信息 |
| `POST /messages/{message_id}/acknowledge` | 显式确认无需回复的通知 |
| `POST /stop`、`POST /messages/{message_id}/resolve` | 任务管理者停止线程，或人工结清待确认的消息。原消息和处置理由保留审计 |
| `GET /evidence`、`POST /evidence`、`GET /evidence/{id}/content`、`DELETE /evidence/{id}` | 列表、发布、读取和撤回证据。附件下载校验当前受众，撤回由发布者或授权管理者执行 |
| 设备授权与设备 WSS | 独立于 Task API，提供兑换、续期、撤权、心跳和待领取信号。WSS 只下发绑定和游标相关的提示 |

CLI 沿用结构化 JSON 输出。命令候选包括 `weora collab join`、`sessions`、`send`、`claim`、`reply`、`status` 和 `publish`。Skill 教 Agent 如何选择明确目标、何时发布证据及何时停止。原生 hook 或通道只承担会话识别和唤醒，CLI 调用统一应用服务。前端根据错误码区分未接入、设备离线、已撤权、目标不匹配、幂等冲突和结果待确认。

## 8. 共享证据与联调收尾

- 开发者或 Agent 在本地明确选中要发布的片段或文件，确认任务和可见范围。发布内容保存来源标识、提交 SHA 或运行版本、测试环境及发布人。服务端按文本、结构化契约和测试产物设置允许类型、大小与留存期。附件先写对象存储，提交发布记录时复验授权并绑定内容哈希，未完成的上传到期清理。文件内容按外部数据处理，拒绝凭据和未获准来源的共享。
- 全部联调消息面向本任务参与者。界面在发送和发布入口说明范围。原生聊天历史留在本机，其他 Agent 可以按任务权限检索已经发布的快照。撤销后同步停止索引命中和后续下载。受众和来源策略与联调消息的领取权限分别检查。
- `reply_to` 关联提问和回应。单向通知无需回复。线程支持停止、超时、限制自动来回轮数和人工继续。联调通过以可核对的测试环境、代码版本及复测记录为证据。完成联调后仍按现有任务验收规则更新 Task。

## 9. 难度与验收

**总体偏高。** 现有项目成员、任务协作、PostgreSQL 和通知模式可以复用。主要未知量是已打开会话的原生投递、客户端差异及故障后的回执语义。Web 页面主要读消息和状态，复杂度集中在本地适配和后端并发边界。

| 验收项 | 通过条件 |
| --- | --- |
| 两人真实联调 | 两个账号、两台电脑、两个仓库。Codex 和 Claude Code 在各自原会话内完成提问、查证、反馈及复测，消息与测试证据在 Task 中关联 |
| 多窗口与重开 | 同一电脑同时开两个会话，只有指定会话可领取。原 ID 恢复后可续接，清空、分叉和换账号不会继承旧绑定 |
| 重试与掉线 | 同幂等键并发只写一条消息。通知丢失后补拉。领取响应丢失或连接器崩溃后，同请求恢复或标记待确认，不把旧请求自动发给新会话 |
| 撤权与隔离 | 在断线、在线及并发领取时撤销成员、设备或绑定。新请求、查询、下载和过期绑定的回复被拒绝。跨工作空间和项目 ID 不可访问 |
| 安全与留痕 | 原生审批仍生效，重复联调达到停止条件后终止。日志可关联消息与操作者，无法检索凭据及未发布的本地内容 |
| 运行与恢复 | 在 PostgreSQL 测实际事务竞争。模拟 Redis 与 API 进程故障验证补拉。监控待领数量、最旧待领时间、待确认数量、按客户端分类的唤醒失败和授权拒绝 |

迁移新增设备和联调相关记录，历史任务保留既有访问策略。发布时按工作空间启用。关闭入口时停止新绑定和新通知，保留消息和审计供有权限的人员排障，恢复后按服务端状态续接。验收分别记录单元、PostgreSQL 集成、真实客户端兼容矩阵和两台电脑联调结果。

本稿已核对仓库权限模型、客户端帮助和公开协议。Windows 原会话绑定、唤醒与跨机联调等待真实客户端验证。
