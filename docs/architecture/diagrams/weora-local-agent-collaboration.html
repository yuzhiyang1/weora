Weora · 目标架构

本地 Agent 跨机协作

开发者把正在使用的 Codex 或 Claude Code 会话加入联调。Agent 在各自电脑上继续工作，通过 Weora 找到对方、提问、回传证据并复测。

系统架构

Weora 管理项目、消息和共享材料。两个本地连接器分别负责把消息送进准确的原生会话。

一条问题怎样进入同事的原会话

以「订单分页接口返回空列表」为例。前端 Agent 提问，后端 Agent 结合已打开的会话查代码并回复。

关键设计约束

设备与会话绑定
开发者登录 Weora 后登记设备，从原生会话内显式加入联调。服务端签发绑定 ID，关联工作空间、项目、成员、设备、客户端配置和原生会话 ID。重连恢复原绑定，切换账号或客户端配置后重新验证。目录仅显示获准的会话和在线状态，仓库、分支与工作摘要由用户授权发布。
可靠投递与恢复
PostgreSQL 同事务保存消息、目标投递记录和审计事件，按发送会话与幂等键去重。WSS 用于通知目标会话有新消息，重连时按绑定查询服务端待处理记录。目标会话通过连接器领取正文，服务端按消息 ID 原子登记领取。重复通知只会触发查询，已领取消息不会重新分配。领取后失联时按已知回执对账。对必须直接注入正文的适配器，结果不明时记为待确认，能证明未交付或支持幂等投递时才自动重投。
客户端适配与隔离
CLI + Skill 提供发现、提问、领取和回复能力。连接器按客户端能力选择原生队列、hook 或主动读信。空闲时可唤醒的会话由适配器唤醒，忙碌时按会话设置等待安全边界。多个窗口各自绑定。Agent 继续用本机权限和原生审批，来自同事 Agent 的内容携带来源标记，按外部输入处理。
授权历史与附件
会话所有者选择要发布的消息摘录、接口约定与证据，平台生成带来源、版本、发布者和受众的快照。消息和快照读取分别鉴权。索引与附件下载沿用快照权限，撤权后停止新增投递与下载，已有接收副本由对应保留政策处理。
联调线程与终止
一个联调线程绑定项目，可关联 Weora 任务，记录问题、回复、提交 SHA、测试环境和验证结果。双方各自在本地仓库工作，通过约定的测试环境或共享契约复测。线程设置轮次上限、有效期和人工停止。撤权、设备离线、会话未恢复、等待人工审批都能从状态中辨认。

实现难度

总体偏高，最难的是原生会话投递和故障恢复。 项目授权、消息落库、会话目录和附件访问可以沿用 Weora 的模块边界。真正需要逐个客户端验证的是，应用已经开着、同时打开多个会话、执行到一半或刚刚重连时，消息能否进入正确的那一个。

  1. 最高难度 · 本地适配。 Codex CLI、Codex Desktop 和 Claude Code 分别维护兼容矩阵。记录能否绑定原会话、唤醒空闲、等待忙碌和确认接收。以实际客户端行为作为能力依据。
  2. 高难度 · 投递与撤权。 重点验证连接器在注入前后崩溃、服务端重复下发、设备凭据撤销、跨项目读写和旧会话恢复。避免串会话、重复执行和撤权后补发。
  3. 中高难度 · 跨端联调。 用两个账号、两台电脑、两个仓库跑通「提问 → 接口查证 → 修复 → 复测」。产物需带接口版本和测试环境。Agent 停止条件与有副作用操作的审批也在同一场景验证。

目标设计以 Weora 服务端中继和存储为部署前提。参考 Reason Network 的原生会话发现与投递机制，Weora 自行管理会话注册、项目授权和消息持久化。

会话在线领取和提交回复依赖 Weora 可达。设备离线期间，新消息留在服务端，重连后恢复领取。
