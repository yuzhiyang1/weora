# ADR 0019：多模型连接与主要 Key

- 日期：2026-11-05。
- 状态：已实施。
- 依据：用户要求保存多个厂商、模型和 Key，在额度不足时手动选择主要使用项；保持平台、技术栈和审批边界。

## 决策

一条模型配置表示一组名称、预设厂商、模型和 Key。同一厂商、同一模型允许多条不同 Key。团队目录只有一个 `primary_id`，新任务和新主 Agent 会话读取其完整配置；预算由目录共用。

目录复用 `console_setting_versions` 与 `console_setting_heads`，使用独立 `kind=models`。连接元数据、主要选择及预算存入公开值结构，逐条加密后的 Key 映射存入既有秘密字段，HTTP 只返回存在状态。所有修改以目录版本执行 CAS，原子保存整个快照，因此并发编辑不会产生多个主要项或丢失另一条连接。

模型提供方固定为 DeepSeek、OpenAI、Anthropic、Google Gemini 和 Moonshot/Kimi 中国区。模型目录从锁定的 `pi-ai@1.3.0` 导出；Web 读取后端目录，不再独立维护厂商和模型列表。Python 与 Pi 协议均限制提供方白名单，客户端不能指定 API 地址。构建、类型及测试在当前依赖上完成，不升级 SDK。

切换主要配置追加版本，不能修改已有 Run 或 Session 的模型配置引用。已有任务的续接继续使用锚定运行的快照，新任务及新主会话才能采用新主要项。移除备用项只改变最新目录，旧版本继续用于历史运行。当前主要项需先切换再移除；跨厂商编辑必须明确输入新 Key。

运行预算的三个字段允许独立留空。`budget` 保留 `null`，表示使用保存预算时的部署默认值；同一版本另存 `effective_*` 整数值，公开目录以 `effective_budget` 返回实际预算。执行装配仅使用该冻结预算；切换 Key、修改名称及部署默认值变化都不重新解析已有版本。只有再次保存预算才采用新的默认值。旧目录中的显式整数继续有效，原单配置 API 仍返回整数。前端比较草稿基线时同时检查输入与实际预算，防止两个空值配置掩盖并发生效值变化。

## 兼容与运行边界

- 无目录时读取原 `kind=model` 单配置或部署默认值；第一次写入将原元数据与加密 Key 纳入目录，旧行及其版本引用不变。无须新增数据库表或执行额外 DDL。
- 保留旧单配置 HTTP 接口，公开查询投影到当前主要项；所有新写入统一使用目录 CAS 指针，避免旧接口与列表各自维护一个当前版本。旧客户端升级后需刷新再编辑。
- 运行快照只包含不透明配置版本与无秘密的执行参数。凭据由 Python 从对应团队及版本解析，再通过专用 stdin 传给 Pi；HTTP、事件和运行快照不携带 Key。
- 预设厂商不仅是 UI 选项。`model_profile` 冻结提供方，Python 适配器传递提供方，Pi 注册并选择对应 SDK 提供方。保留旧 DeepSeek 别名的原请求 ID，不静默换模型。
- 检测只查询固定官方模型接口，限制超时、响应大小和重定向。单模型接口允许服务端把模型别名解析为版本 ID；检测成功表示认证及模型可见性，不代表余额充足或执行授权。
- 协调范围若另有主/Worker 模型覆盖，需要与所用配置的厂商兼容；切换主要项不会修改这些明确设置，也不会改写已有主会话。

## 维护

升级 Pi SDK 后运行 `pnpm --filter @weora/pi-runtime export:providers`，提交生成目录及配套适配变更。运行时测试校验后端每个预设都能通过实际 SDK 注册与解析，目录漂移会使测试失败。

接口、验收和限制见 [多模型配置验收](../development/model-connections-acceptance-20261105.md)。
