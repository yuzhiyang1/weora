# ADR-0012：模型预算、工具执行时限与重拟审批分离

- 状态：已接受
- 日期：2026-10-21

## 背景

真实云效 Maven 验收发现：长工具等待同时被 Python 执行器、Pi 子进程和 Node 总计时器记为模型超时。模型仍有推理预算时，容器构建就被 300 秒模型时限中断。另外，“要求重拟”仅复制原范围，未唤醒 Agent，文字补充与真实授权范围可能不一致。

## 决策

1. 新任务分别冻结累计模型等待预算与整体执行时限。部署默认整体 1800 秒，模型预算仍由原配置控制；不允许 Agent 自行延长。旧快照缺少整体字段时保留旧行为，配置往返必须保存两个字段。
2. Python Runtime 等待 Tool 返回时暂停累计模型等待计时；Node 使用相同语义。平台整体时限仍覆盖全部执行，工具自身的精确命令、执行时限、租约、取消与撤权检查不放宽。
3. 模型预算耗尽记录 `MODEL_TIMEOUT`；新快照整体到期记录 `RUN_TIMEOUT`。不能将超时、被中断工具或缺失退出码改写成成功。撤权和超时竞态中，优先保留已确认的访问撤销事实。
4. 人类补充意见保存为新的 `REVISION_REQUIRED` 计划记录，保留原范围供审计，但不具有执行授权，也不可直接批准。Run 排队唤醒普通规划 Agent；它按补充理由提交新的 `plan.propose`，新版本再次等待人工审批。状态同步中断由维护任务补偿，不重放写操作。
5. Console 明示“等待重拟”，不展示批准占位记录的按钮。只修正文案不算完成重拟；必须由 Agent 修改实际 scope，再由人类核对精确路径、命令、动作和远端目标。

## 验证边界

- 模型预算与整体预算通过无网络子进程、真实 Pi 事件循环和事务集成测试分别覆盖；模拟测试不替代真实 Maven 验收。
- 加长整体预算不代表提高 Maven 工具时限，不代表批准自动合并、部署或访问其它仓库。
- 本决策与模型供应商、Git 托管平台无关，平台持有计时、授权和审计，Agent 只提出与执行获准步骤。
