# ADR 0015 同 Task 的持久消息与新 Run 续接

- 状态：Accepted（用户已明确授权本轮范围）。
- 日期：2026-11-03。
- 关联：[整体方案](../architecture/execution-layer-upgrade.md#14-第一轮实施持久任务续接2026-11-03)、[ADR 0014 总体提案](0014-continuous-agent-execution.md)。

## 决策

先实施消息与 Task 的持久关联、后续输入保存、同 Task 新 Run 和必要历史装配。保持现有技术栈、模块边界、Pi v1 协议及审批机制；立即插话、原生会话日志和语义协调后续实施。

1. Task 表示持续目标，TaskInput 表示新的输入，Run 表示一次执行尝试。同 Task 最多一个非终态 Run，活跃期间只保存输入，完成后顺序续接。
2. 飞书使用精确话题/引用和显式新任务标记判定归属，关联限定在同一发起人及固定来源、路由和项目授权范围。保留显式 @ 的触发条件。
3. 输入先持久化；创建 Run、dispatch 与分配输入同事务提交。Beat 补偿恢复和公平扫描；Redis 与进程内会话均不是权威消息队列。
4. Pi 每个 Run 仍创建新的 Agent。平台向本轮请求附加有界的初始目标与已成功问答，重新校验历史来源；历史只作数据参考，不具有审批效力。
5. 每次执行保留不可变 AgentVersion、Skill 和原项目快照。新 Run 不复制计划、批准或工具回执；私有 Console 输入不能借群任务发到群里。
6. 用户取消前排队的消息不再自动执行；取消后新的明确输入可以续接。永久停止 Task 的生命周期另行设计。
7. 同 Task 的持久输入已有成功轮次、且该历史重新授权通过时，外部话题仅因 `budget_exceeded` 或 `has_more` 截断可以继续；保留原消息/材料预算和 `partial` 快照，向模型明确覆盖缺口。新任务、无有效历史、读取失败、解析缺口、撤权或过期不适用，仍等待上下文。预算截断不能覆盖已有读取失败原因，已保存的 partial 在再次装配时也必须执行相同判断。

## 影响

增加 `task_inputs`、`task_threads` 和 Task 输入序号，需迁移及协调服务发布。已有输入的数据库禁止直接降级；发布回退保留账本和兼容读取能力。

有界问答窗口能支持连续任务协作，但不能恢复完整 Pi 工具循环，也不保证模型记住窗口外细节。等待审批期间的补充不会替换当前计划，用户仍通过已有审批接口处理当前计划。本轮不增加前端界面、普通消息自动触发或完整 Router。

## 验证

验证 HTTP/CSRF、并发幂等、有序领取、单活跃 Run、启动失败重试、撤权、取消、保留期、飞书回报关联和旧审批隔离。分别记录 SQLite、隔离 PostgreSQL、真实 Pi 加脚本化提供方，以及尚未进行的真实渠道与外部模型联调。
