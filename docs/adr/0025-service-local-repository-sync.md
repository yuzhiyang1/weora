# ADR 0025 服务端预同步与固定提交读取

- 状态：第一期已实现，默认关闭。真实 CodeArts 大仓和多节点存储待验收。
- 日期：2026-11-10。
- 承接 [ADR 0007](0007-selected-repository-readonly-snapshots.md) 和 [ADR 0008](0008-selected-repository-approved-sandbox-and-branch.md)。

## 现状

运行准备按 Run 为每个选中仓库创建独立裸库，再拉取固定提交。协调中心接单前的读文件和目录也会准备临时裸库，读完即回收。两个入口都可能重复传输相同的代码。浅拉取减少历史范围，当前提交的静态资源仍可能远大于日常调研所需的文件。

## 设计与实现

1. **项目仓库后台同步。** 已通过连接校验的存量仓库会自动纳入，新仓库使用原「校验连接」入口登记。部署复用 Celery Beat，并用 `weora.repositories.sync` 队列控制同步并发。首次只取登记分支最新提交及其 Git 文件内容，后续复用同一裸库增量拉取。LFS 正文、子模块、标签和其他分支不自动拉取。
2. **Run 和接单评估固定本地提交。** 每个工作空间、仓库和连接版本独立持有随机缓存 ID。同步验证目标提交并建立固定 Git 引用后才发布 SHA 和同步时间。新 Run 以 `service-local-v1` 冻结读取方式，并在第一次成功准备时保存 SHA、缓存 ID 和同步时间。接单评估在首次读取后固定 SHA 和连接版本。两个入口都直接读本地 Git 对象。
3. **Agent 使用受控的本地读工具。** 第一阶段复用 Run 的 `repo.file.read` 与接单评估的文件、目录读取。工具仍以已选仓库和相对路径定位，授权、文件大小和输出预算继续在平台校验。Run 的目录工具和文本搜索可在此基础上另行接入。
4. **改码与构建按审批准备独立工作区。** 从已经固定的本地提交生成隔离工作区，按目标仓库的构建配置执行。现有归档大小预算独立于同步配额。支持大仓库同步之后，完整构建仍需单独验证归档或工作区物化的资源边界。

## 同步与失败语义

- 同一连接版本由数据库行锁和有界租约领取。Git 同步成功后用租约和当前连接版本比较交换，重复投递、Worker 退出或过期结果不会覆盖已发布记录。失败按同步间隔重试，进程退出后由过期租约恢复。
- 分支查询使用现有短命令预算。HTTPS 继续检查低速连接，整个后台同步有独立总时限。首轮失败清理本次新建目录；增量失败保留原裸库和旧提交。单仓大小在 Git 传输期间检查，属于应用层限制，部署还需给持久卷配置硬容量上限。工作空间硬配额、按阶段字节和耗时统计留给后续治理。
- 新 Run 采用有效期内最近一次同步成功的提交，详情 API 返回实际 SHA 和时间。首次未同步、最近一次失败、已过有效期或本地文件丢失时，相关仓库返回对应错误；该 Run 不会在任务启动阶段补做远端拉取。已有 Run 仍读取原提交。其余健康仓库继续提供证据。第一期按固定间隔更新，暂不提供逐任务强制刷新或使用过期版本选项。
- 当前连接版本的已发布提交保留固定引用。连接版本升级后，旧连接立即失去读取授权，后台在七天宽限期后回收对应裸库。活动连接中的历史提交暂不自动回收，达到单仓上限需管理员按实际保留要求处理。暂停或归档项目不主动清理仍可恢复的连接。

## 部署与回退

先执行 `alembic upgrade head`，然后在 API、Run Worker、协调 Worker、Beat 和同步 Worker 中统一配置 `WEORA_REPOSITORY_SYNC_ENABLED=true` 与 `WEORA_REPOSITORY_CACHE_PATH`。读写进程需要访问同一受控持久卷。不要让各容器分别使用各自的临时目录。同步 Worker 可先用一个并发槽运行。

```powershell
uv run --no-sync celery -A weora.bootstrap.worker:celery_app worker --pool=solo --queues=weora.repositories.sync --hostname=weora-repo-sync@%h --loglevel=INFO
```

默认同步总时限 900 秒、同步间隔 300 秒、提交有效期 900 秒、每仓 2 GiB。可分别用 `WEORA_REPOSITORY_SYNC_TIMEOUT_SECONDS`、`WEORA_REPOSITORY_SYNC_INTERVAL_SECONDS`、`WEORA_REPOSITORY_SYNC_MAX_AGE_SECONDS` 和 `WEORA_REPOSITORY_SYNC_MAX_BYTES` 调整。进程按环境配置选择调度，改配置后需重启相应进程。

使用 `GET /api/v1/workspaces/{workspace_id}/projects/{project_id}/repositories/{repository_id}/sync` 查看状态、最后成功 SHA、时间和失败码。已获授权的管理员可以调用现有连接校验入口提前排队。排队成功到 `READY` 之间由后台领取。首次接入时可等目标仓库就绪后发起运行。

回退时关闭预同步并保留数据库迁移与持久卷。新 Run 恢复原按运行准备方式，已绑定的 Run 可以继续从原缓存读取。此前已创建但未绑定本地提交的 `service-local-v1` Run 会报告预同步未启用，需重新启用或重新发起。旧资料型任务和原按运行准备的快照保持兼容。

## 实施与验收顺序

1. 用真实本机 Git 对象和独立数据库验收首次同步、同仓单租约、两个 Run 和接单评估复用本地对象、增量更新后旧 Run 固定提交、同步失败后恢复及旧连接回收。
2. 部署验收用实际 CodeArts 大仓测首次同步、增量流量、超时与恢复。检查服务重启后仍能读同一提交，连续发起两次任务时 Run 不访问 Git 远端。
3. 大仓构建另验归档或工作区物化的资源边界。多节点部署另验共享存储的锁、可见性和容量管理。

本地 Git 夹具验证了复用方向。首次同步包含 32 MiB 不可压缩资源，第二次只改 README，本地对象库增加 275 字节，两个固定提交都可读取。该结果只验证 Git 对象复用，实际 CodeArts 链路、共享存储、资源上限和部署仍待验收。

实现回归使用独立 SQLite 数据库和实际本机 Git。首次同步后，两个 Run 和接单评估都未触发新的远端读取。用例覆盖同仓租约、失败后恢复、连接更换、旧缓存回收以及归档超限停止。迁移在隔离的 PostgreSQL 17 上完成升级、回退和再次升级。
