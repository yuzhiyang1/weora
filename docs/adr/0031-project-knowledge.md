# ADR 0031 项目知识库与 PostgreSQL 发布状态

- 状态：Proposed
- 日期：2026-11-18
- 产品流程见 [TeamAI 行为对照](../product/project-knowledge-design.md)。

## 决策

1. PostgreSQL 是知识正文、版本、发布状态、召回和审计的权威来源。索引、摘要和健康报告可由原始记录重建。
2. 普通经验贡献自动发布。导入、修订和晋升按各自的确认流程进入版本管理；发布与审计在同一事务完成。归档移出召回范围，保留历史证据。
3. 搜索从登录成员的工作空间开始，有项目时沿用 Projects 应用服务的授权规则，并合并共享知识。客户端调用平台 API；设备令牌与浏览器各自沿用现有认证方式。
4. PR、飞书消息、会话和代码提交作为可追踪来源。通过已有来源适配器取得内容，归属和访问权限继续由其所在领域验证。
5. 召回和采纳按用户与根会话归因，发布版本使用条件更新保护。正式 Skill 的包校验、版本与分发仍由 Skill Registry 管理。
6. 仓库知识读取已授权的固定 Git 对象。每个仓库连接的可重建索引基线与证据版本同事务更新。连接版本变化或仓库停用后，历史索引保留审计用途，并从当前项目查询撤下。检索按已有同步提交的 Git 对象计算来源新鲜度。
7. 组织发现和清单导入以项目登记仓库为执行边界。批量按仓库独立提交，操作收据与索引版本同事务保存，可在客户端中断后按原请求重放。
8. PostgreSQL 保存每个正文版本的派生词项。新版本与词项同事务入库，评审发布通过版本指针切换召回结果。共享知识和项目知识分别按领域统计词频，然后统一排序。索引回退只删除派生数据，重新迁移可从原始版本回填。
9. 类型和逻辑相对路径共同确定可覆盖的资源。项目发布后覆盖同类型、同路径的共享资源，项目检索与关系使用有效版本。条目的路径身份由首个版本确定，正文修订继续使用原路径。旧版来源链接与条目 ID 仍可用于查看历史证据。
10. 召回采用 ICU 词边界，并在连续单字之间补足词项。索引回填、发布和在线查询共用同一版本的分词实现与 ICU 字典。切换分词版本时，数据库事务从原始正文重建词项和统计值。
11. 规则适用路径随正文版本保存。读取时按当前项目的发布规则和授权代码证据派生 `MAPS_TO`，相同方向的显式关系优先。每个展开后的路径模式必须唯一命中一个仓库来源。关联边随发布、仓库索引变更或授权变化重新计算。
12. 召回计数按成员、根会话和条目归因，记录本范围内实际展示的正文版本。正文打开和评分共用同一有效采纳记录；显式人工反馈可纠正评分，审计保留原判定与修正。工作空间可启用评分，对平台提交只包含版本与判定。
13. 召回运行日志与长期采纳计数分开，保留 30 天。运行日志记录请求跟踪标识、会话摘要键、是否命中、返回版本及关联 ID。会话报告按成员和项目授权，记录到期清理不影响长期采纳计数。CLI 分享提醒只读取本机的短期命中质量摘要。
14. 原生会话手工分享须确认本机脱敏快照。PostgreSQL 按显式授权范围保存不可变归档版本、发布者与请求追踪标识。归档可独立浏览，知识召回只查询已发布知识条目。
15. 知识采纳评分固定到该成员发布的归档版本。计划和提交均按该版本的采集时点筛选作者在同一根会话内实际看到的条目版本。判定审计记录所用归档版本。历史归档可继续读取，缺少采集时间时需重新预览并发布再用于评分。
16. 自动归档按有人值守和无人值守分别授权。工作空间记录 `off`、`ask`、`auto` 的历史，设备按成员明确绑定的项目目录处理。自动写入在同一事务内复核有效的管理员策略，归档版本记住所用策略。交互会话使用 6 小时闲置门槛，无人值守由启动器在原生进程退出后登记。
17. 团队会话评分标准是管理员发布的项目或共享资产，项目标准覆盖同名共享标准。会话标签固定到标准版本和脱敏归档版本，按评分人和人工或模型来源分开记录。标签查询默认显示每组最新结果，可读取历史。团队会话标签独立保存，知识采纳继续按召回条目计数。
18. 归档的后台评分独立授权。PostgreSQL 在事务内核对成员、作用域、运行模式、确定性采样和每日用量，领取时固定归档与标准版本。失败与租约过期后可续做，至多四次。成功标签和结算同事务提交，策略停用后拒绝在途标签写入。限额按工作空间、成员和 UTC 日期核算，点名判定计入用量并保留手工入口。
19. 本机会话可以直接评分。设备先将转录脱敏，再交给评分客户端。平台只登记设备生成的会话标识哈希和内容指纹，按作者、项目和证据版本保存标签。公开归档使用单独的标识，转录查询及采纳评分入口排除本机证据。团队只发现已提交标签的本机会话，试跑无写入。
20. 本机后台评分由设备保存已结束会话的脱敏快照，领取时声明能够读取的精确版本和指纹。平台在项目、成员和运行模式范围内分配租约，未持有快照的设备不接手该版本。团队归档与本机记录共享会话来源哈希和正文指纹，相同评分标准的后台任务去重。旧归档在按原会话重放发布时补齐派生指纹。
21. 询问模式从有权读取的团队评分标准中推荐采样命中且未评分的版本，成员可主动点名覆盖建议。预览不登记平台证据、不分配租约。设备将确认码绑定项目、脱敏证据及标准版本，确认时重新核对可用性，跳过后释放本机快照。确认的标签通过点名评分入口审计，提交失败可复用原判定和请求键。
22. 合并评分默认关闭，成员可为单次评分显式开启，管理员可按运行模式设置默认值。相同证据、首选客户端及模型的标准共用调用，每项仍固定自己的版本并写入独立标签。后台合并组按一次调用核算日额度，将整组租约与结算集中处理。客户端仅在整组标签有效时提交。已确认的点名批次在设备端先保存整组判定，可在提交失败后续做。
23. 目录评分标准以 `SCORER.md` 及可见 UTF-8 附件组成版本。PostgreSQL 保留附件的相对路径、正文和整包 SHA-256，评分计划和后台续做始终读取固定版本。评分客户端把 `${TEAMAI_SCORER_DIR}` 展开为逻辑目录，将附件正文随该标准传入模型。评分结果保留目录校验值，标准列表只返回摘要。
24. 自动采纳沿用对应运行模式的自动评分授权及同一成员的每日额度，另需启用召回采纳评分。平台凭根会话归因哈希、证据摘要及采集时点，在同项目和同一成员的召回记录中生成采纳问题。每个领取固定会话与正文版本。作业状态、评分结果、实际记账及条目审计在同一事务提交。普通打开及人工反馈与采纳评分共用已有反馈账本。
25. 管理员可发布单文件 `teamai-adoption.md` 覆盖内置标准。项目版本优先，依次回退到工作空间版本和内置标准。重置通过新版本归档当前覆盖，保留历史。服务端展开模板并固定展开结果、逻辑证据路径、标签表、阈值和模型。后台结算同时保留评分客户端原标签及通过阈值换算的采纳判定。显式预览展示原标签和模板来源。
26. 同一证据版本、相同首选客户端与模型的采纳问题默认共享一次调用，单组最多 20 条。每个问题继续拥有独立租约、原标签和反馈审计，数据库按调用标识计算日额度。结算事务核对完整标签集合，提交失败时整组回滚。重试沿用上次调用中仍待判定的问题及原证据和模板。
27. 团队开启后台合并后，普通标准与兼容的采纳问题可共享同一个调用标识。普通标签与采纳判定保留各自的账本，在单个事务校验并提交完整调用结果。运行模式或采纳授权撤销时整组终止。按调用标识跨账本去重核算日额度，续做使用原调用中仍待判定的成员。
28. 点名采纳问题按本机会话指纹或本人归档的采集边界解析实际召回版本。试跑只读取证据和标准。正式调用将普通标签、采纳结算和幂等收据同事务提交，按一次调用核算额度。已打开的条目可以保留评分标签，采纳账本仍遵循现有团队开关与去重规则。
29. 分享前的评分询问默认推荐命中采样的普通标准，成员可主动点名生成式采纳问题。设备预览码固定证据摘要、召回正文版本和标准版本。确认后按分组调用评分器，先在设备上保存判定再提交。带采纳问题的确认在写入事务中复核对应运行模式的评分策略。失败后沿用同一确认码及模型判定重试。
30. 回归套件绑定项目仓库和对比矩阵。任务固定评分标签、会话标识和启动提交，由管理员登记。默认任务与开放提案中的任务用于判断回归覆盖，开放提案按套件与评分标准唯一。套件行锁串行化任务登记和提案发布。已发布或放弃的提案保存终态、操作者和时间。
31. 每次基准运行的任务、来源仓库版本、两组资源提交、截止时间和试验编号在创建事务内固定，试验判定按编号一次结算，重试复用原结果。按任务、工具及重复编号配对，两边判定工具、模型或推理强度变更时排除该对。报告按任务和工具检查回退，未判定或不可比较的试验使门禁保持未完成。
32. 基准执行由 CLI 使用本地固定 OCI 镜像，试验从浅检出复制独立可写工作区。代码和该侧资源只读挂载，评判容器只收到任务、成功标准及受限证据。模型访问通过独立 Docker 内部网络的网关，执行器先把判定写为本机回执，再向已授权的 PostgreSQL 控制面结算。
33. 自我改进沙箱只生成结构化草稿，CLI 将任务绑定到原评分标签及 Git 起点。资源路径限于支持交付的规则、Skill、子 Agent 和团队说明。资源差异与任务在同一 PostgreSQL 事务内写入开放提案。每个修订保留资源基准、变更前摘要及任务标识，续写检查原修订及资源摘要。生成的提案须经资源交付核验后才能发布。
34. 生成提案的交付先按修订预留 Git 提交和冻结文件摘要，再写入该提案专用分支。续写以已登记提交为父级，用远端分支租约保护并发变更。控制面读取项目登记的 GitHub PR，核对仓库、提交和文件内容。收到合并事实后，还须有固定到同一基准及提案提交、覆盖完整套件且通过门禁的基准运行，任务才进入默认套件。
35. PR CI 从受信任 GitHub 事件定位项目提案，控制面先回读冻结分支、文件和基准，后按提交与运行尝试幂等创建完整矩阵。每次新尝试成为该修订的当前检查，旧尝试不能更新结论。提交状态指向比较报告所在的 Actions 运行。合并确认只接收最新尝试的完整通过结果。
36. 每周及手动调度由资源仓库的 GitHub Actions 触发，单次 GitHub 运行编号固定一个操作，重跑时沿用原编号。控制面按项目、套件、操作、评分标准和操作者恢复原修订。调度只交付本次修订，已被更新替代的修订保留收据，GitHub App 令牌限于安装的资源仓库。
37. 人工干预统计独立于会话归档、召回和评分。设备按明确绑定的目录采集根会话累计值，工作空间可关闭上报。重放以工作空间、项目、成员、宿主和会话摘要去重，旧上报不能减少累计值。周报读取团队累计计数、均值和三种运行模式的会话数。转录、提示词、路径和原始会话 ID 保留在设备。
38. 工作流统计从可信 GitHub Actions 完成事件定位仓库、运行号和尝试。CLI 回读该尝试与作业，按首个作业启动到最后结束计算耗时。PostgreSQL 在项目和登记连接内留存已完成尝试及上报者。同次重放返回原收据，周报只从最大尝试号计数。取消保留运行数和耗时，所有作业跳过时排除该次运行。
39. 设备沿用活动上报的根会话标识和权限，只提交提示轮次及四类归一化 Token。Codex 从输入扣除缓存，线程累计值优先于分 rollout 累计；Claude Code 按消息标识去重并归入其本机子会话用量。控制面按最新有效观测原子替换 Token 四个桶，旧设备的缺失值不会覆盖已测数据。周报显示累计量及运行模式分布。
40. 原生根会话的产出按首次结束结算，交互会话闲置六小时，无人值守由退出入口登记。设备在同一 Git 仓库的起止提交间归因本机成员的提交，托管评审必须包含其中的已推送提交。知识经验由 PostgreSQL 使用工作空间、项目、作者和来源摘要确认。结算绑定先前已接受的结束快照并冻结 Token 与人工干预计数。发布重试不增记，统计可重复归类到不同产出，终端只显示聚合。
41. 团队趋势采用相邻两个 UTC 七天窗口，根会话以首次 Stop 归日，恢复后的计数和失败信号可更新原日。CLI 汇总相邻事件中不超过五分钟的间隔，从原生记录提取可计价请求。定价及去重都在设备完成，控制面按项目及请求日保存累计请求数和估算金额。重放不会重复结算，缓存比例直接使用会话 Token 计数。
42. 设备 Git origin 用于匹配活动项目登记地址。仅当前同步缓存的提交、采集覆盖和 Git blob 均一致时，干净 checkout 的根目录才复用登记仓库索引。设备差异及子目录使用自身快照，关联结果随证据版本入库。登记连接失效后读请求隐藏不可访问的连接详情。
43. CLI 离线输出将代码清单、Markdown 证据和图谱保存在调用者指定的 teamwiki 目录。CLI 和控制面构建包共用确定性提取器；离线源码不上送，快照不自动进入 PostgreSQL 发布流程。每个来源的基线指向已完整写入的内容版本，根图谱从各来源的基线派生，可通过重复导入修复。
44. 远端离线批量在同一个 teamwiki 写锁内逐仓库提交，完成后刷新公共图谱。续做沿用本机运行记录与原输出目录。网络只用于仓库发现和对象读取，裸库与托管平台凭据均为临时输入。仅由远端 Git 对象确认的完整快照可依远端 HEAD 跳过克隆。
45. 代码设计生成消费已固定的文件事实和关系。离线模式将组件设计、架构、图谱和场景文档绑定到源索引版本，保存成功产物并在同版本补齐缺项。AI 客户端只读取本次生成所需的结构化证据，产物路径由 CLI 计划决定。确定性图谱与生成正文一起在来源索引导航中浏览。
46. 平台生成计划固定到代码库身份、提交或设备快照、采集范围和实际文件事实的摘要。文档发布与重新索引复用仓库连接或设备快照的事务锁。已发布文档、检索和审计通过现有知识表提交，变化的证据撤下旧设计版本，等价的全量重提取保留设计。平台在服务器根据事实生成确定性图谱；设备生成的正文只可写入固定计划的组件、架构和场景位置。
47. 代码导入在索引提交后启动同一深度生成流程。批量运行分开保存索引回执及设计结果，续做优先补同一份证据的设计。证据已变更时拒绝旧任务。离线目录写入共享同一个导入锁，平台设计各步骤通过项目权限及基线校验单独提交。
48. 跨仓库关系使用固定索引中的导入或配置数据标签匹配当前可用证据。仓库内已有候选时保留其优先级，跨仓库候选有歧义时不生成。项目查询只确认同一项目且仍可读取的两个发布页，并核对其对象哈希。离线根图谱重建时使用同一算法，关系记录两个来源版本。
49. 产品调和沿用 TeamAI CLI `1104f305` 的 `src/wiki-engine/knowledge-reconciler.ts`，分别生成产品映射和普通资源的关系候选。Weora 以项目已发布且路径在 `product/` 或 `teamwiki/product/` 的文档作为产品输入。管理员在 PostgreSQL 中刷新项目映射，按两端发布版本过滤失效关系，并按产品文档写审计事件。普通文档与规则的候选通过现有评审发布。离线图谱记录正文摘要，预览只读，重复发布内容一致时保留文件时间。
50. Swift 按同文件和 SwiftPM 的完整目标路径解析可见协议。不同包的同名目标分开处理，源码目标与测试目标各自解析，同名歧义时不生成关系。独立 TOML、INI 和 CONF 只提取明确的章节及键名，为配置跨仓库关系提供声明证据。
51. JS/TS 调用使用 Python Tree-sitter 及固定版本的 TypeScript/TSX 语法包，平台和 CLI 独立锁定同一依赖版本。索引按语法树提取静态绑定、词法遮蔽和调用行号，以目标模块当前的导出声明区分已确认调用和模块级推断。增量索引复用未变文件的事实并重新解析关系。原始源码作为解析输入，调用事实和关联对象随现有索引发布。
52. iWiki 双轨导入先完成普通知识发布，再从本次授权原页归纳业务接口、外部知识源和术语表。平台用服务端标记的独立知识文档存放章节，按工作空间和项目维护版本，成员可发起修订并沿用评审。每个运行和章节固定请求键，待审冲突时整批回滚。离线以托管区块更新单份 Markdown，逐章审核核对草稿生成时的区块摘要。
53. iWiki 代码关系由本次获准导入的原页提供术语，控制面只解析当前项目发布的代码证据。关系与原页导入版本同事务保存，记录目标发布版本及匹配依据。读路径校验两端和仓库连接的可见性，同一操作重放不重新绑定。离线图谱按原始页面 ID 更新并核对导出页与代码证据的内容摘要。
54. Go 调用和路由使用固定版本的 Tree-sitter Go 语法包。采集优先纳入 `go.mod`，以当前文件所在的最近模块和包声明确认导入目录，测试文件按包作用域参与。调用定位要求唯一的函数或同包接收者方法声明。模块文件发生变化时，索引复用其余文件的事实并重算调用边。
55. Swift 的调用语法、函数和类型可见性由固定版本的 Tree-sitter Swift 语法包提取，沿用 SwiftPM 默认目录的目标边界。索引在目标内核对唯一声明、词法绑定和可能的成员遮蔽，保留推断置信度。度量、评审差异、平台详情和离线图谱基于相同事实重算调用边。
56. JS/TS 模块在固定快照中读取最近的已索引 `tsconfig.json` 或 `jsconfig.json`，按 `baseUrl`、`paths` 和相对继承定位模块。直接依赖保留中转文件，调用与接口实现沿再导出记录唯一的实际声明。类型导出只参与类型关系。解析范围限定在已索引的仓库文件中，npm 包和无法确认的目标由原有检索流程处理。
57. 经验晋升、质量修订、维护和健康报告可按当前项目读取可见的共享根目录和启用目录。CLI 选定项目时默认使用合并视图，支持 `--project-only`。单条写入按资产的原范围进行，工作空间管理员可在合并视图批量归档及更新置信度。共享质量草稿只读取共享示例。晋升锁定源版本和首发路径，保留源目录，在资产原范围核对目标冲突。新增规则、文档和 Skill 的知识贡献与晋升使用同一范围的 PostgreSQL 事务锁。已待审或发布的晋升占用该逻辑路径，驳回后释放。Skill Registry 首次发布和恢复已发布资产时在同一事务锁下检查占用，冲突返回 `SKILL_PROMOTION_PATH_CONFLICT`。知识审核在首次发布前复查同范围的 Registry，遇到历史冲突时保留待审稿。操作标识、原稿和原范围用于网络重试，审批复用现有发布事务和 Skill Registry。
