# ADR-0011：代码源身份、项目仓库与构建环境分离

- 状态：已接受
- 日期：2026-10-20

## 背景

团队使用云效，但未来可能迁移到自建 GitLab。仓库仍属于项目，一个项目可以选择多个仓库；设置页只组织配置入口，不能隐含扩大 Agent 的可读范围或远端权限。交互参考用户提供的 Multica 截图，沿用 ADR-0010 的本地组件，不复制其源码、样式或品牌。

## 决策

1. Git 克隆、推送继续使用每个项目仓库的 Git 凭据。工作空间 `code_sources` 只保存代码托管 API 身份；Git 密码、SSH 密钥不能假定等价于 MR API 令牌。
2. 当前实现云效 API 连接，GitHub/GitLab 等平台仍可登记 Git 地址，但不宣称已实现对应平台的 API/OAuth。仓库显式关联同工作空间、同组织的代码源及平台仓库 ID；未关联的旧部署配置保持兼容，不自动迁移秘密。
3. API 令牌只写、加密、不回填。省略保留，明确空值清除；更新使用版本 CAS。切换组织或 API 地址必须重新提供令牌。停用、清除、轮换后，旧任务的身份版本失效；依赖漏装配时失败关闭，不回退到其他连接。
4. API 地址只接受云效官方 HTTPS 主机，禁止携带路径、用户信息、端口。新自助连接创建 MR 前，先调用只读 GetRepository 核对返回 ID、克隆地址、网页地址与冻结 Git 目标；不匹配时不进入 POST。保存配置只标记“远端未验证”。
5. 构建配置只选部署管理员预置的不可变镜像 Profile。任务冻结 Profile、镜像指纹和 argv 建议，镜像变更要求重新发起任务；表单不能登记任意镜像、挂载路径或环境变量。建议命令不是执行许可，执行仍需人工批准的精确 argv、路径及动作。
6. 审批权限与工具名称是两个概念。`plan.propose` schema 从领域常量导出允许枚举，并说明 `sandbox.file.write → file.write`、`sandbox.command → command.run`、`sandbox.diff → git.diff`，不让普通 Agent 猜测权限字符串，也不增加自动批准能力。

## 接收诊断边界

飞书接收进程的状态采样独立于持久 Inbox 和成功 ACK。界面分别展示进程心跳、连接生命周期、协议 PONG、业务帧、供应商事件及 Inbox/Run；人工补收不能作为自动入口证据。诊断写入超时不能阻塞 ACK，旧配置或过期心跳不能显示为当前连接成功。SDK DEBUG 日志在所有处理器前转换为固定代码，禁止保存握手 URL、正文或异常原文。

## 影响与限制

- 新迁移：`20261020_0015`，旧仓库新增字段可空，历史任务不会自动绑定新身份。
- 代码设置入口 `/settings/code`；项目仍是仓库归属和选仓授权来源。
- 当前只开放预置构建环境及命令建议，不包含通用私服凭据管理、任意 JDK 安装或完整原始构建日志留存。
- 供应商事件未进入接收连接时不能靠补造事件“修好”验收；必须保留入口未通过事实。
- 云效只读目标核对契约参考：[GetRepository 官方文档](https://help.aliyun.com/zh/yunxiao/developer-reference/getrepository-query-the-code-base)。

## 追加：已有部署配置接入（2026-10-21）

- 设置页为工作空间 owner/admin 展示可匹配原仓库的部署连接；普通成员不能枚举。GET 不读取秘密文件，只展示仓库、组织和不可逆映射指纹。
- 用户确认后，POST 只接收仓库 ID、仓库版本和映射指纹；API 不接受令牌、凭据引用、文件路径或目标地址。后端仅从当前工作空间明确登记的连接读取 API 身份。
- 创建代码源和关联原仓库在一个事务内完成，仓库行锁加版本 CAS 防覆盖。原 Git 凭据和构建配置保留；重复请求复用同一身份，不覆盖已轮换令牌，也不重新启用已停用身份。
- 关联会推进仓库连接版本；只要任务快照保存了连接版本，就必须复验，不因未启用 Git 对象只读协议而跳过撤权检查。没有版本字段的更早历史资料保持原兼容语义，不自动获得新执行权限。
- 保留旧部署配置用于明确回退和兼容，但显式绑定新代码源的任务不得回退到旧 API 身份。新任务冻结数据库身份版本与管理员预置的构建镜像指纹。
- 审批界面区分“登记远端 / 基准与 MR 目标分支”和实际的 `weora/` 专用推送分支；目标是 master 不意味着授权向 master 推送。
