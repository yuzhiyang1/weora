# ADR 0017：协调执行生命周期与独立仓库来源

- 日期：2026-11-04。
- 状态：已实施，验收见 [差异修复验收](../development/superagent-gap-acceptance-20261104.md)。
- 依据：固定 Super-agent `59e6c4059d513a5a63c482aee884c95e4ea89fa0` 的源码、测试与本地差异复现。

## 决策

继续采用 Python/FastAPI、PostgreSQL、Redis/Celery、Pi/Node 和模块化单体。
协调模块拥有 Ticket、Assignment、消息归属、Eval、活动与持久副作用；原生 Runs 拥有租约、
执行预算、计划审批和运行结果。源事件、模型回合成功、任务目标完成分别记录，不能互相替代。

Main 使用持续 Pi 会话决定接单、追加、停止与回复。Worker 可以在本 Run 内管理命令和子会话；
子会话继承模型、工具范围、预算及来源约束，只能管理自己的后代，不能批准计划。
长命令五秒转后台；有活动时保留 Run 槽位。等待人工、结束或撤权时回收后代，未知结果进入恢复处理。
不恢复丢失的宿主进程句柄，不自动重放工具来猜测结果。

跨 Run 的工作文件使用现有 Delivery Artifact 保存有期限的工作区快照。
恢复必须属于同 Task、同仓库与固定基线，且文件仍在本轮批准的写入路径内；旧审批不继承。
Git 发布默认使用专用新分支。续写原 PR 时引用同 Task 的成功交付记录，重新审批提交与推送，
平台冻结分支和旧 SHA；只构造以上次提交为父的新提交，再用远端 SHA 比较交换更新。
它保留分支隔离、未知写不重放和审批机制，不允许写保护分支或引用别人的任务。

代码平台接单采用独立的 `code_hosting` Task 来源，不伪造飞书 Inbox。
仓库、远端、项目与外部账号映射由管理员配置，来源只能使用已登记连接；凭据不进入控制台或模型。
GitHub 和 Codeup 各自翻译事件协议。外部作者未绑定有效成员时不接单，也不借管理员身份执行。
已订阅讨论另行补读，即使仓库消息游标未改变，也能收到 PR 的 CI 与评审事实。
来源与原生交付共用供应商正文解析，但分别验证各自授权；讨论定位不伪造原生交付或 Run。

每条任务输入都登记派生 Run 的保留期限。任一输入撤权或到期时，同步拒绝模型、历史与工具访问，
并缩短派生副本期限，由既有清理流程清除正文。原生提交后、协调绑定前的撤权窗口也保存清理依赖。
这些登记是限制读取与保留期限的内部应用端口，不授予访问权，不开放给模型或 HTTP 客户端。

## 结果

- PostgreSQL 仍是协调状态的权威来源；Redis 仅承担通知与 Celery 传输。
- Main、Worker 会话冻结各自模型，配置变更影响新会话或新授权，不改写既有会话事实。
- 模型瞬时失败只重试当前模型请求；会话投递只有确认尚未执行工具时才能重试整次投递。
- PR 关闭/合并是生命周期事实。轮询观测时间与可信关闭时间分开；未处理人类输入优先保留。
- 配置和会话通过现有 Console 的协调中心管理，revision CAS 防止覆盖他人更新。
- 迁移 `20261104_0018` 只扩展 Task 来源 CHECK 约束，不取消审批或改变已有任务受众。

## 验证边界

本轮通过真实 PostgreSQL、Docker、Pi 集成以及前后端回归；代码托管 HTTP 使用契约夹具。
不将上述结果写成已完成真实 GitHub/Codeup 外部写验收。保留的平台差异与接入要求见验收文档。
