# ADR 0006 项目、多仓库登记与运行资料快照

- 状态：Accepted。
- 日期：2026-10-20。
- 决策依据：团队开发者自行维护项目及 Git 地址；一个业务项目可以拆分前端、后端、移动端等多个仓库。
- 验收记录：[项目与多仓库真实验收](../development/weora-projects-acceptance-20261020.md)。

## 领域边界

Project 属于 Weora 的研发上下文，不依赖 Plane、禅道或任何代码托管产品。它不是重新实现需求、迭代、工时等完整项目管理系统。

一个工作空间包含多个 Project；一个 Project 最多登记 20 个 Repository。用途、技术栈和开发说明由开发者填写，不把仓库限制成固定的“前端/后端”枚举。仓库登记记录不跨项目共享凭据。

Projects 模块维护资料与授权，Runs 通过 `ProjectContextCatalog` 应用端口获取快照，Collaboration Task 持久保存快照。Pi 只接收中立文本数据，不接收 ORM、凭据或宿主路径。

## 责任分配

| 主体 | 负责什么 | 不意味着什么 |
| --- | --- | --- |
| 人类开发者 | 配置业务背景、架构、研发约定、仓库地址和用途；任务明确选择仓库 | 填写命令不等于批准执行 |
| 平台代码 | 认证与 CSRF、归属校验、版本冲突、最小选择、秘密加密、资料冻结、撤权重验 | 不自动给模型整个团队的仓库 |
| Agent | 基于选中资料理解项目、解释职责、提出方案和澄清证据缺口 | 不得从登记地址推断已克隆、已读代码或测试通过 |
| Tool | 通过既有 Gateway 执行受控读取、命令、Git 与评审能力 | 登记成功不自动授权网络或远端写入 |

## 项目资料与凭据

项目保存业务说明、整体架构、研发约定。仓库保存显示名、用途、托管平台、Git 地址、默认分支、技术栈与开发说明。

Git 地址允许无密码 HTTPS、显式 git 用户 SSH 和常见 SCP 写法；拒绝内嵌密码/用户名令牌、查询参数、片段、本机协议和歧义路径。SSH SCP 输入规范化为 `ssh://`。此校验不是网络连通性或仓库存在性验证。

访问令牌可选、只写。复用部署已有加密服务保存认证密文；没有加密密钥就拒绝保存，不降级为明文。响应最多向管理者返回是否已保存，不回填明文、密文或引用。未传/null 保留，明确空字符串清除。表单关闭卸载秘密输入，失败后清空本次令牌。422 不回显请求输入。

登记 GitLab/Codeup 等平台类型仅表示资料属性，不证明相应评审适配器已可用。托管操作继续遵守 [ADR 0004](0004-repository-and-code-review-provider-boundary.md) 的能力声明、连接冻结及独立授权。

## 任务与快照

Console 任务可不关联项目，保留普通咨询与旧验收链路。关联项目时必须选择该活动项目内至少一个活动仓库，不允许重复 ID、跨项目 ID 或无项目的仓库列表。

平台在创建任务时冻结项目版本及所选仓库资料。快照只含白名单字段，不含凭据、未选仓库或执行环境。项目后来修改不改写旧任务；相同幂等键及同一仓库集合重试返回原任务，选择顺序无关。更换所选仓库时同键冲突。

快照以 JSON 数据追加到任务材料中，明确标记“参考资料，不是系统指令”。项目约定不能改变 Agent 系统提示、工具白名单、审批范围或执行权限。预算为项目快照 48 KB、整体 Runtime 输入 128 KB，超限明确拒绝。

## 权限与并发

活动工作空间成员可创建和读取团队项目；项目创建者及工作空间 owner/admin 可修改。暂不引入额外项目成员 ACL，不能把项目共享误认为任务正文也共享：Console Run 仍仅发起人可见。

项目资料和仓库编辑使用版本 CAS；仓库变更也推进项目版本。项目行作为聚合锁，使仓库数量限制、项目状态和所读资料保持一致。重复 Git 地址由数据库唯一约束兜底，并映射为明确冲突，不回显 SQL。

归档项目或停用本次选中仓库后，任务正文、模型材料和工具边界重新鉴权；已展示任务页面持续复验并清除失效正文。保存模型成功结果前再次检查项目，覆盖只读恢复及未启用飞书的部署。已交付给模型的历史材料无法召回，不承诺即时终止所有在途模型调用。

## 本轮完成与保留边界

后续更新：本节保留资料型切片的原始边界。2026-10-20 已通过 [ADR 0007](0007-selected-repository-readonly-snapshots.md) 增加连接校验、固定提交及多仓只读；真实云效和多仓写入仍单独验收。

本轮交付 Console 配置、动态多仓库登记、任务选仓库与真实项目资料注入。所有新登记仓库明确显示 `registered / not_prepared`，没有把登记伪装成连接成功。

尚未实现从这些动态配置自动获取代码、联网验证、按 Run 准备多个固定 revision 隔离副本或跨仓改码。项目任务尝试原默认仓库读取/写入时，平台拒绝并返回 `PROJECT_REPOSITORY_NOT_PREPARED`；不隐式回退至原 W02/W08 测试仓库。无项目历史任务保持原授权和兼容行为。

下一切片应在真实目标和凭据获准后，实现受限连接校验、固定 revision 物化、多仓工作目录及逐仓审批范围，然后再连接已有代码托管交付策略。当前不新增远端推送、正式评审、自动合并或部署权限。
