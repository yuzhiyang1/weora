# ADR 0022 任务电脑续接与测试凭据

- 状态：已采纳；真实端到端验收结果单独记录。

此前电脑以 Run 隔离，后续运行需要调试人员迁移登录配置；账号登录也依赖后台代填。这只能证明人工辅助联调，不能作为 Weora 自主完成业务任务的验收。

电脑改为按工作空间、发起用户、Task 和权限模式派生标识。同一 Task 的顺序运行继续使用原浏览器页面与登录态，新任务、其他用户、其他工作空间和观察模式各自隔离。每次操作仍使用当前 Run 的来源授权和执行租约。人工停止后不能由 Worker 自动重新启动。旧版按 Run 创建的配置不会自动导入新电脑，保留卷由管理员按原归属清理。

用户通过带身份与 CSRF 校验的配置 API 登记测试凭据。凭据保存于电脑模块自己的加密表，绑定用户、工作空间、精确来源及测试协调话题，一天后失效并支持撤销。只读话题不得获取或填充。模型只看到引用、标签和来源；填充工具在应用端解密，再由电脑服务核对当前页面、字段所属 frame 来源及快照，密码只允许写入密码字段。提交表单仍是独立、可审计的点击动作。明文不进入工具参数、结果或普通 API 响应。

Worker 可读取页面可见正文，不能把 ARIA 快照未列出标题解释成网站未渲染。遇到无凭据、验证码或判断障碍时，通过电脑请求接管，并向协调器报告 blocked 与协助步骤。人类在现有电脑面板接管和交还后，通过原飞书话题继续任务；Worker 首先核对当前状态，不重放考试创建等业务写操作。

飞书主 Agent 自行生成简短结论并选择真实截图。正文超过 240 字时拒绝入 Outbox，要求模型修改；详细记录保留在 Run。产品验收必须记录是否存在后台代操作、改写报告或直接修复运行数据，不能把这些操作算作自主闭环。

执行协议最多声明 64 项工具，单轮最多执行 64 步，后端按 Run 持久化相同的业务工具预算；预算耗尽返回明确错误。声明容量和调用预算是两类不同限制。该容量覆盖登录、多页操作和协调报告的组合，继续保留模型时间、总执行时间、输入输出大小及副作用未知禁止重放的约束。原生执行失败必须形成可回传的问题，引导用户通过原话题明确重试；不静默改写失败状态。

网关与父进程传输共用 `shared.runtime_limits`，检查点帧数按工具预算乘四派生为 256，单帧和新增输出限制不变。真实子进程回归必须覆盖 30 次调用通过、超过 64 次停止，避免只验证 SDK 的测试遗漏父进程旧限制。供应商工具名保留可读语义，旧哈希名称仅对已知工具做模型侧转换并保留原名称，不做模糊匹配或重放历史工具。

迁移 `20261107_0020` 仅新增短期凭据表，不改变原有任务数据。回退前撤销或备份需要保留的测试凭据，再回退表结构与服务；浏览器卷不随数据库回退删除。
