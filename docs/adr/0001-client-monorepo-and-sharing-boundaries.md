# ADR-0001：客户端 Monorepo 与跨端共享边界

- 状态：已接受
- 日期：2026-07-30

## 背景

Weora 当前只有 Web 管理端，但未来计划提供桌面端和移动端。如果继续用 `frontend` 表示整个客户端，会默认把 Web 技术实现当成所有客户端的共同基础，后续拆分目录、依赖和构建链的成本会持续增加。

另一方面，当前没有第二个客户端。现在抽取通用 SDK、跨端 UI 和平台接口，会产生只有一个实现的抽象，无法证明它们是真正稳定的共享边界。

## 决策

客户端采用根级 pnpm workspace：

```text
apps/
  web/
  desktop/       # 未来按需创建
  mobile/        # 未来按需创建
packages/        # 出现真实共享需求后创建包
```

依赖规则如下：

1. 客户端应用可以依赖共享包，共享包不能依赖客户端应用。
2. 所有客户端优先共享数据契约、领域行为和设计令牌。
3. Web 与桌面端在同为 React DOM 技术栈时可以共享页面实现。
4. 移动端保留原生交互和渲染实现，不以复用 Web 页面或 CSS 为目标。
5. 网络、存储、通知、文件系统等平台能力由应用内适配器实现。
6. 在第二个使用方出现前，不创建空的 SDK、通用 UI 或平台接口。

## 影响

- 当前 Web 代码迁入 `apps/web`，根目录统一管理 pnpm 版本、锁文件和跨应用命令。
- Docker 构建上下文调整为仓库根目录，以读取 workspace 元数据。
- 将来增加桌面端或移动端时，不需要再次改变仓库一级目录。
- 共享包的建立会稍晚于应用目录，但每个共享边界都必须由真实复用需求证明。
