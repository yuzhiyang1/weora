# ADR 0020 通过 OpenBot 接入虚拟电脑

- 状态：已采纳，容器联调证据单独记录。

Weora 通过私有 HTTP 网络调用 OpenBot Supervisor 和电脑服务。OpenBot 的两项服务在构建时锁定上游源码版本，Weora 维护镜像配方、逐电脑凭据补丁与 Xfce 适配。现有项目代码沙箱和虚拟电脑分别部署。

电脑按工作空间、用户和 Task 隔离（续接决策见 ADR-0022），每次操作绑定当前 Run 的权限与租约。私有控制台 Run 可由归属用户接管，飞书 Run 需要管理员登记专用协调话题和观察或测试权限。Weora 校验工作空间、运行归属、话题来源授权和工具租约，OpenBot 管理容器、浏览器与控制权。电脑在用户启动或白名单内的首次 Agent 导航时创建，停止后保留该任务的工作文件和浏览器配置。人工停止后需要从控制台显式重启。

飞书观察权限采用独立浏览器配置，仅允许登记来源的 GET/HEAD，并禁止点击、填表和桌面接管。测试权限使用测试环境和已授权人员。浏览器请求与截图通过 `browser.evidence` 关联到持久化产物。观察证据与代码交付验证分别判断，截图不构成代码修改或测试通过的证明。

飞书回执采用一条原生图文消息：主 Agent 通常用 100～200 字说明结论、关键事实和必要限制，最多附两张截图；完整报告保留在运行记录。模型只选择截图产物编号，由平台验证其属于同一 Task、未过期且内容校验通过后上传，群消息正文不堆叠编号。图片上传失败可重试；正式发消息前进入发送结果未知状态，沿用既有 Outbox 幂等与对账流程，避免重复发布。应用需要具备飞书图片上传权限。

Xfce 和 Chromium 使用同一个 Xvfb 显示。控制台轮询完整桌面帧，人工输入携带接管请求 ID，由电脑服务校验后执行。接管时等待 Agent 当前动作结束，交还后 Agent 重新获取网页快照。第一版 Agent 能力限定为浏览器工具，电脑服务禁用 Shell 和破坏性重置。

默认桌面网络不对外开放。管理员登记可导航的测试站点，测试站点单独接入内部网络。Supervisor 的 Docker Socket 访问留在控制网络。部署和验收入口见 [运行手册](../../runtimes/openbot/README.md)。
