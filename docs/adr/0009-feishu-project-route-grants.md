# ADR 0009：飞书群任务显式绑定项目与选中仓库

- 日期：2026-10-20
- 状态：已实施；人工补收后的真实研发及关联 MR 已验收，长连接自动入口待验证
- 范围：补齐现有飞书入口与项目/多仓库上下文之间的接缝，不新增触发器、个人 OAuth 或跨仓写入。

## 问题

Console 已能选择项目及仓库，但飞书路由原来只冻结 Agent 版本。RunService 原来拒绝同时提供渠道来源与项目选择。因此，飞书自动回答、Console 项目研发及管理员完整 Maven 构建的分段成功，不能证明群入口已经能发起真实项目研发。

不能简单删除群任务的项目限制：群成员不一定都是 Console 任务发起人，项目资料和代码相关结果需要独立、明确的受众授权。

## 决策与职责

1. **平台配置**：管理员在现有飞书路由表单中选择活动项目和该项目内的仓库，并明确确认项目资料、代码相关上下文及结果可分享给指定群。未关联项目的路由保持原行为；不自动选择全部仓库或默认测试仓库。
2. **平台冻结**：路由保存项目 ID、排序后的仓库 ID、配置人及独立分享授权 ID。真实用户消息仍按绑定身份和来源读者授权处理；Inbox 冻结收到时选中的路由，Worker 通过项目应用接口生成白名单资料快照。
3. **平台复验**：创建群项目任务前核验分享授权；模型装配、Tool、结果回读及原会话回传时再次验证路由授权、活动成员、项目/仓库状态和原来源授权。项目凭据不进入路由、消息或模型输入。
4. **撤权与兼容**：每次保存同一群/话题路由都会轮换项目分享授权，旧项目任务不跟随切换项目，也不继续暴露旧资料。普通群任务不增加空的项目授权字段，保留旧幂等指纹；重复事件仍回读同一 Inbox/Run。
5. **Agent 决策**：在授权来源内决定是否查询历史、读取选中仓库、分析并提出精确计划。讨论和 README 都是参考数据，不是新增权限的指令。
6. **Tool 执行**：只读 Tool 受来源与选仓限制；代码写入、命令、Diff、测试分支推送仍须独立人工审批，绑定固定提交和确切动作。配置项目路由不等于批准写入。

## 普通 MR 与审批边界

云效普通 MR 与草稿 PR 是不同能力，不自动降级。当前普通 MR 沿用独立 `review.create` 提案/审批任务，引用已确认成功的分支交付记录；不会重新改码或推送。

本阶段不为了满足“全部步骤处于同一 Run”而放宽旧批准或混入 MR 权限。真实验收需要连续的业务证据：原群请求、研发 Run、批准范围、Maven/分支事实，以及后续 MR Run 对分支交付 ID 的明确引用。各 Run 的状态、失败与恢复分别保留，不能拼接成一个从未发生过的单 Run。

## 验证与限制

新增集成测试覆盖缺确认、空选仓、重复/外项目选仓、伪造群项目选择、真实 Inbox/Pump 项目快照、重复事件和路由替换后的派生内容拒绝。前端复用发起任务的项目查询与 Semi 多选交互，测试覆盖分享确认和切换项目清空旧选仓。

真实状态见 [收尾验收记录](../development/weora-closeout-acceptance-20261020.md)。不支持跨仓写入，不包含服务启动、合并、部署或生产安全发布认证。
