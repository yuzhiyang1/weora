# ADR 0008 选中仓库的审批沙箱与独立分支交付

- 状态：Accepted；真实验收结果单独记录，不以此状态表示全部外部联调完成。
- 日期：2026-10-20。
- 承接：[ADR 0007](0007-selected-repository-readonly-snapshots.md)、[ADR 0004](0004-repository-and-code-review-provider-boundary.md)。

## 范围与职责

项目支持多个仓库，任务显式选择需要读取的仓库。本切片让一份审批计划操作其中一个固定提交，不实现跨仓写入或原子发布。

平台代码鉴权、冻结提交与连接版本、归档、绑定镜像、持久化审批、限制路径与命令、保存执行证据并代理凭据。Agent 决定提案与调用顺序，不能批准自己的计划。Tool 提供读取、提案、沙箱改文件、执行命令、Diff 和分支交付；只读接入或模型文字都不产生写权限。

Projects 的 `RepositoryArchiveExporter` 可选端口提供固定提交归档，可信装配桥 `ProjectExecution` 通过 Projects / Runs 应用接口协作，不跨模块读取 ORM。宿主归档路径不成为模型参数。导出前后与每次操作重新验证任务、选中仓库、成员授权和连接版本，不回退旧默认测试仓库。

## 沙箱环境

`WEORA_PROJECT_SANDBOX_ENABLED` 默认关闭。管理员可设置 `WEORA_PROJECT_SANDBOX_IMAGE` 为完整不可变镜像 ID/digest，独立于既有浏览器沙箱镜像。本次提供 `runtimes/sandbox/java/Dockerfile`，包含 JDK 17 与 Maven；不是在每次任务中联网临时安装。

执行容器继续无网络、非 root、只读根文件系统并限制 CPU、内存、PID 和时间。Git 凭据只在后台交付代理短时使用，不注入沙箱或模型。镜像纳入远端计划连接指纹，变更后不能复用原推送审批。

目前没有项目级环境选择页面、自动依赖镜像构建服务或通用私服凭据管理。独立 Java 编译与 `mvn --version` 成功不能替代业务项目完整 Maven 构建，后者需要明确 JDK 版本、依赖来源、私服身份及受控准备流程。

追加的管理员 Maven 准备流程将联网依赖解析与断网 `clean verify` 分开。公共源配置不包含认证；依赖镜像只携带缓存、无凭据离线设置和文件哈希清单，不携带源码或宿主个人 `.m2`。联网准备阶段不运行项目测试；`mirrorOf=*` 不是通用网络防火墙，不能据此宣称可安全携带私密凭据。私服身份仍需在可信依赖代理/准备设施单独管理，不复用 Git 密码或云效 API 令牌。

`WEORA_PROJECT_SANDBOX_RESOURCES` 提供有界 JSON 资源预算，必须绑定独立项目镜像。后台在 Run 首次绑定时冻结镜像和预算，不能中途替换；Java 多模块构建可提高内存、临时空间和命令时长，不影响原浏览器镜像，也不增加网络、宿主挂载或特权能力。模型工具不提供这些配置参数。配方与操作边界见 `runtimes/sandbox/java/README.md`；真实构建是否通过仍以专门验收记录为准。

## Git 与 MR 分开

新增 `delivery.branch.push`，只发布批准的有界 Diff；必须分别批准 `git.commit` 与 `git.push`，并具备真实测试和 Diff 证据。后台在临时裸库生成单父提交，不 checkout、不执行 hooks、过滤器或仓库脚本；不使用个人工作目录。

业务幂等键派生唯一 `weora/` 测试分支。推送使用显式同名 `HEAD:refs/heads/<branch>`，以空预期 lease 保证仅创建不存在的分支，绝不覆盖已有分支。前后核对默认分支；基准已前进则拒绝并要求新计划，不擅自合并或变基。

分支交付记录单独使用 `branch:` 标记。`SENDING/UNKNOWN` 不自动重推；前端提示人工核对，不调用 MR 核对接口冒充恢复。只有确认的非分支评审记录才满足 `pr.create` 完成条件。

SSH 公私钥或 HTTPS Git 密码只解决 Git 认证，不等于云效 MR API 令牌。本切片的动态项目接入尚未配置评审 API 身份，明确拒绝项目 `pr.create`；不套用旧测试仓库配置，不伪造 MR 链接，不合并或部署。后续需为项目登记独立的评审 API 配置与最小权限身份，再沿用供应商适配器。

自动测试区分 Fake Docker、真实本机 Git 与真实云效/Docker/模型证据；验收记录见 [项目写入验收](../development/weora-project-write-acceptance-20261020.md)。本机配置不是生产可用证明，未知远端状态必须保留。

后续完整 Maven 构建、固定依赖镜像、资源预算与无网络重复验证见 Maven 验收记录（内部记录已移除）。该记录是管理员构建验收，不冒充新 Console/Agent Run，也不扩展为合并或部署授权。

## 追加：已交付分支的普通 MR（2026-10-20）

用户进一步提供独立 API 身份后，新增 `review.create` 独立动作和 `delivery.review.create` Tool，只消费 `source_delivery_id` 指向的已确认分支，不重新改码、执行命令、提交或推送。普通 MR 不是原 `pr.create` 所承诺的草稿，不改变云效草稿能力仍未验证的事实。

平台验证源 Run 私有可见性、工作空间、原仓库实时授权、原审批与证据保留期限，匹配仓库、基准、路径、远端和目标分支。MR API 连接由管理员按工作空间/仓库登记，指纹与 Git 连接分开冻结；跨平台迁移或配置变更须重新审批。创建前后查回已交付分支提交和 master，不能把漂移分支当作原测试结果。

同一已交付分支的 MR 使用稳定业务键和确定性 UUID，数据库主键 CAS 防止不同 Run 并发创建两次；换 Run 也不能绕过未决结果。`UNKNOWN` 仅允许只读核对；适配器能确定尚未进入 POST 的预检失败记为 `NOT_SENT`，也必须通过新版本人工审批才允许再尝试。失败 Tool、恢复证据与尝试次数保留，不能将原失败覆写成成功。只读恢复注入最新持久交付状态，写工具仍禁用。

`WEORA_HOSTING_API_TOKEN_FILES` 仅接受管理员明确登记的绝对文件路径，短时读取 API 令牌；不覆盖同名 Git 凭据引用，不把秘密放入计划、模型或响应。当前是部署级配置，没有 MR 凭据管理页面。

真实云效协议已补齐：末页 `x-next-page` 可回填当前页，必须由当前页、总页数及总记录数一致佐证，否则仍拒绝；列表用 `state`，创建/详情用 `status`，两者冲突拒绝；`webUrl` 可以是仓库首页，MR 链接必须精确核验 `detailUrl` 与登记仓库及 localId，不能放宽到任意供应商 URL。

真实普通 MR 创建及只读核对见 MR 验收记录（内部记录已移除）。不自动合并或部署，也不把普通 MR 称为草稿。
